# 《悉达多》Gold 人工复核与现有输出问题

## 已确认的现有模型错误

1. **乔达摩 / 佛陀被拆成两个节点**
   - 当前 `workspace/.../cast.json` 同时存在 `乔达摩` 与 `佛陀`。
   - Gold 要求 `乔达摩 = 佛陀 = 世尊 = 释迦摩尼` 必须合并。

2. **悉达多出现可疑错误别名 `悉达多·乔达摩之子`**
   - 本书正文中的主人公悉达多是婆罗门之子，并不是乔达摩之子。
   - Gold 不接受该别名。

3. **第 4 章把乔达摩 → 悉达多确认成普通“师徒”过强**
   - 原文确实称佛陀为悉达多“最后一位恩师”，所以不能说二人毫无师承/启发关系。
   - 但第 3 章明确写悉达多不皈依、继续独自求道。
   - Gold 因此要求：接受“精神启发者/恩师”，拒绝“正式师徒/皈依弟子”。

4. **现有 ledger 有重复关系**
   - 例如第 1 章“结伴同行”等候选重复出现，第 3 章“朋友/布施供养”也有重复。
   - evaluator 后续应增加 relation dedup 指标，否则召回看似变高但图上会出现重复边。

5. **把“学做生意”直接泛化成传统师徒有风险**
   - 悉达多确实从迦摩施瓦弥处学习经商，也受其指导。
   - Gold 接受“经商指导/商业关系”，但不建议无条件归入传统师徒。

## 需要用户重点人工复核的边界项

这些已放在 `optional_relations` 或采用更细标签，不作为最硬的召回目标：

- 悉达多 ↔ 瓦稣迪瓦：朋友、摆渡学艺、精神引导、前辈师长之间的标签边界。
- 悉达多 ↔ 乔达摩：恩师/精神启发者 与 正式师徒 的边界。
- 悉达多 ↔ 迦摩施瓦弥：商业共事、雇佣、指导的标签粒度。
- 一次性行为边：守候、施救、担忧、反抗等是否应进入最终关系图。

## 建议的评分优先级

1. 人物同一性与别名合并
2. required relation precision / recall
3. forbidden relation error rate
4. evidence exact-hit rate
5. relation dedup rate
6. optional relation coverage（低权重）
