## 1. 目标

做成一个人人可查、人人可补的**图书人物关系库**：

- 查：任何人不用注册就能打开库里的书，看关系图、导出图片
- 补：库里没有的书，用户用自己的模型 API Key 分析，结果进入公共库，之后所有人都能直接看

运营方只承担服务器和存储，不承担模型费用，不收费。

## 2. 与内测版的差别

| 方面 | 内测版（PRD-beta） | 公益版 |
|------|------|------|
| 模型费用 | 运营方承担，靠用量上限控制 | 用户填自己的 API Key，用自己的额度 |
| 注册 | 邀请码，分批放号 | 浏览不用注册；贡献新书需要登录，开放注册 |
| 用量上限 | 书数、字数、全站每日 token | 去掉 token 与字数上限；保留单个文件大小、每人同时分析数，防止占满服务器 |
| 分析结果 | 归上传者，按用户隔离；同一文件秒传共用（§4.4） | 默认进入公共库，所有人可看；秒传是主路径 |
| 示例书 | 运营方预置几本 | 不再单独区分，库里的书就是示例 |

沿用：PNG 导出、反馈、TXT 上传、秒传的命中规则（PRD-beta §4.4）。

## 3. 用户与路径

| 用户 | 路径 |
|------|------|
| 读者 / 学生（主力） | 搜书名 → 打开关系图 → 章节聚焦、看人物、导出图片；全程不用注册 |
| 贡献者 | 登录 → 填 API Key → 上传库里没有的书 → 用自己的 token 分析 → 成功后进入公共库，署名可选 |
| 维护者（运营方） | 处理反馈、下架有问题的书、维护公版书清单 |

## 4. 规则思路

### 4.1 公共库

| 规则 | 说明 |
|------|------|
| 搜索 | 按书名、作者、人物名搜索 |
| 一本书多个结果 | 同一本书可能有不同版本的文件、不同模型的结果；默认展示一个，可切换查看其他结果，并标明用的是哪个模型、何时分析 |
| 进入公共库的条件 | 整书分析成功、读完全书；只读到第 N 章的结果只自己可见 |
| 不公开的选项 | 贡献者可选择只自己可见（例如私人藏书、未出版的稿子） |
| 下架 | 版权方投诉或内容有问题时由维护者下架 |

### 4.2 用户自己的 API Key

| 规则 | 说明 |
|------|------|
| 填写 | 在个人设置里填，支持常见的 OpenAI 兼容服务；提交前做一次连通测试 |
| 保管 | 只用于本人发起的分析；界面上只显示末尾几位；可随时删除 |
| 用量 | 分析前预估 token 和大致费用，用户确认后再开始；分析中与结束后显示实际消耗 |
| 失败 | Key 失效、额度用完、服务商报错时明确告诉用户原因；已读完的章节保留，换 Key 后接着读 |
| 进入公共库的模型 | 只有指定名单内的服务商与模型的结果才能进入公共库；其他模型的结果只自己可见（防止自建接口伪造结果污染公共库，也保证基本质量） |

### 4.3 秒传仍是核心

库越大，新用户越不需要自己花 token。上传文件命中公共库里的结果时直接看图，不需要 API Key；不命中时才提示填 Key 自己分析。

## 5. 不做

- 收费、打赏、积分
- 运营方代付 token
- 人工编辑关系图（PRD §5.8）；有错走反馈

## 6. 开放问题

| 问题 | 备注 |
|------|------|
| 版权 | 结果里有原文证据摘录。公版书可以完整公开；仍在版权期的书，公共库只公开关系图、不公开原文摘录，还是不收录，需要先确定，最好咨询法律意见 |
| 数据授权 | 公共库数据用什么协议开放（如 CC BY-SA），是否提供整库下载 |
| 是否开源 | 代码开源可以让别人自建、减轻维护负担；与目前的商业化路线冲突，转公益时再定 |
| API Key 保管方式 | 存服务器（加密）还是只存在用户浏览器、每次分析时带上；影响「关掉网页后分析能否继续」 |
| 同一本书多份结果的默认展示 | 按模型、时间还是反馈数选默认结果 |
| 维护成本 | 存储随书数增长，长期由谁承担服务器费用 |
