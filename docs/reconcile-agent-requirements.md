# 全书总校对 Agent — 基本需求

> 各章分析完成、程序合并人名册之后的最后一轮 AI 收尾。  
> 不重做全书分析，只处理可疑点与有据修正。

## 1. 目标

在「按章挖关系」之后，做一轮**全书级校对**：

- 判断是否同一个人，建议合并
- 处理关系冲突（类型/方向打架）
- 在有原文依据时补漏或修正
- 搞不定的写入待办，不硬改

**不做：** 通读全书重抽关系、无依据大面积改图、一次塞进全部章正文。

## 2. 在流水线中的位置

```text
各章分析（并行）
  → 程序合并人名册 + 改临时 id
  → 程序生成「可疑清单」
  → 【本 Agent】总校对（可跳过，见 §6）
  → 程序应用修改
  → 分析完成
```

状态上建议有：`总校对中` → `完成`。  
总校对失败时：建议降级为「分析完成但未校对」（可出图），不堵死主路径。

## 3. 输入（注入上下文）

每次必带、体积可控：

| 内容 | 说明 |
|------|------|
| 书与范围 | 书名、本次分析到的章、是否截断到某章 |
| 人名册 | 程序合并后的通讯录（id、正式名、别名、重要度） |
| 可疑清单 | **主菜**，见 §4 |
| 各章短总结 | 每章分析结果里的 summary |
| 关系类型表 | 与章分析同一份枚举 |

**不注入：** 全书正文、所有章完整关系列表全文。细账用工具按需查。

## 4. 可疑清单（程序生成，再交给 Agent）

至少包含：

1. **可能是同一个人**  
   - 别名重叠、正式名等于对方别名等（现有合并队列逻辑可沿用并扩展）
2. **关系冲突**  
   - 同一对人：关系类型硬撞，或有向关系方向相反；附带出自哪些章

可选（可后做）：

- 硬关系缺少原句依据
- 总结里提到两人、该章账本却没有关系（仅作「去查一下」提示）

**若可疑清单为空：** 默认跳过本 Agent，直接完成（可用配置强制跑一轮）。

## 5. 工具

需能**跨章**（参数带章 id）：

| 工具 | 用途 |
|------|------|
| 章内搜索 | 在指定章搜关键词，返回命中行（有条数上限） |
| 限量读正文 | 读指定章某一段字符窗口（有长度上限） |
| 取章分析结果 | 查看该章人物、关系、总结 |
| 查人名册 | 确认 id / 别名 |
| 提交校对结果 | 唯一出口：提交结构化修改建议；校验失败返回错误 |

**不要：** 章分析那套「提议新人」、无界读整章、工具直接写文件。

使用纪律：

- 处理可疑项时，优先搜索/回看再下结论
- 合并与改关系尽量带章号 + 原句
- 没把握写入待办，不要硬合

## 6. 输出（结构化修改建议）

Agent 提交一份 patch，由**程序**校验并写回，例如：

- **合并人**：保留谁、去掉谁、理由、依据
- **别名**：给某人增加别名
- **关系**：增 / 删 / 改（类型、方向等），尽量带章号与原句
- **待办**：证据不足、无法自动处理的项

程序应用顺序建议：先合并人（改全库 id）→ 再改别名 → 再改关系 → 更新待办清单 → 标记校对完成。

## 7. 约束

- 单轮工具循环 + 一次提交即可（P0）
- 步数上限可配（建议低于长章分析，任务更聚焦）
- 可使用单独模型配置（若已配置则优先，否则用主模型）
- 禁止无证据重写整本人名册或整本关系网

## 8. 验收（最小）

1. 章分析 + 程序合并后能进入总校对（或无可疑时正确跳过）
2. 给定「两人别名重叠」类可疑项，能建议合并或明确进待办
3. 给定「同一对人关系冲突」，能裁决或进待办，且可回查原文
4. 修改经过程序校验后落盘；非法 type / 非法 id 被拒绝
5. 总校对失败时主流程仍可标为可出图完成（降级策略生效）

## 9. 非目标（本需求不做）

- 长篇波次记忆、NLP 全书扫人名
- 前端图谱与人工编辑 UI 细化
- 强制「每条原句必须搜得到才入库」（可后续加强）
- 多层子 Agent 调度

---

**一句话：** 给通讯录 + 可疑清单 + 各章短总结，配上跨章搜索/读段/查章结果，让 AI 只做合并与冲突校对，输出可应用的修改建议。
