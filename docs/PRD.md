# ZhiYing 产品需求文档（PRD）

| 项 | 内容 |
|----|------|
| 产品名 | **ZhiYing** |
| 一句话 | 上传电子书，Agent 生成可编辑、可防剧透的人物关系图 |
| 文档性质 | 设计汇总 / PRD v0.2 |
| 日期 | 2026-07-14 |
| 状态 | 草案（实现前可改） |

---

## 1. 背景与问题

读中长篇小说时，人物多、称呼乱、关系会随章节变化。读者与创作者往往靠：

- 手工画思维导图
- 把摘要丢给通用 AI 让它画 Mermaid
- 网上搜别人画的关系图（易剧透、不准）

市面缺少顺滑的：

> **上传我的书 → 自动出人物关系 → 可校对 → 可按阅读进度查看**

开源与成品里，完整「整书 → 稳图」方案少；较接近的如 `graph-every-novel(就在上一级目录有源码)` 偏重本地状态机与多层门控，工程重、对模型约束极死。ZhiYing 走更轻、更 Agent 化的路线，但保留出图时必要的结构与过滤。

---

## 2. 产品目标

### 2.1 要做成什么样

1. **主输入：EPUB**（看书主流格式；TXT 非优先，仅作后续兼容）
2. **先建人名册，再抽关系**，减少「同人裂成多个点」
3. **按章分析**，支持只汇总前 N 章 → **防剧透**
4. **关系是多标签**，不是 A–B 只能有一种类型
5. **软硬权重**：泛关系可被强关系在展示上压制；硬关系之间不互相覆盖
6. **证据可解释**：关系尽量带来源章节与原文短句
7. **出图可过滤**：默认可读，不靠蜘蛛网硬撑「全量真实」

### 2.2 明确不做（现阶段）

- 不做成通用写作 IDE / 网文诊断台
- 不追求一次塞进整本长上下文「魔法出图」作为主路径
- 不复刻 graph-every-novel 整套重状态机与多层裁决
- 不把 PDF/扫描版 OCR 放进首期
- 不默认做社交图谱社区（版权与剧透风险）

## 3. 目标用户

| 用户 | 诉求 |
|------|------|
| 中长篇/名著读者 | 理清人物与阵营，复习、写读后感 |
| 网文读者 | 人物爆炸时快速建立地图 |
| 读书会/自媒体 | 导出图做分享（注意版权与剧透） |
| 作者（次要） | 用自己的稿看关系是否乱（本地、隐私） |

## 4. 核心设计原则

### 4.1 中篇与长篇：两种体验，一套账本

| | 中篇（如《百年孤独》量级） | 长篇（如《红楼梦》量级） |
|--|---------------------------|---------------------------|
| 用户要的 | **一张读得懂的全景图** | **可导航的地图册**，不是一张糊墙海报 |
| 默认展示 | 尽量展示主要人物与关系 | 核心子集 + 下钻 + 搜索 |
| 记忆与累计 | 可较轻 | 必须按章入账 + 可切前 N 章 |
| 防剧透 | 弱需求 | 强需求（按章进度） |

实现上不必两个 App：同一套「章 JSON 账本」，**展示策略与默认过滤不同**。

### 4.2 过程松、出口紧

| 松（交给 Agent） | 紧（系统定死） |
|------------------|----------------|
| 怎么读章、是否搜索原文 | 输出结构（人物/关系/事件字段） |
| 推理与摘证据 | 关系类型来自**短枚举** |
| 本章小结怎么写 | 写入前校验；无证据策略可配置 |
| | 展示用软硬权重与出现次数过滤 |

不把模型当「随便写库的上帝」，也不把模型当「只会填死表的表格工」。

### 4.3 记忆与账本分离

| 东西 | 用途 |
|------|------|
| **章总结 / 大总结** | 给 Agent 的**工作记忆**（情节上下文） |
| **人名册 cast** | 认人、别名 |
| **章结果 JSON** | **事实账本**（出图的主要数据源） |

出图以账本为准，不以「大总结复述」为准。

### 4.4 对标但不复刻

可借鉴：

- 关系类型受控枚举
- 导出前「够不够格上图」的过滤思想
- 人物重要度 / 出现统计等**后处理**（图论细节可后抄成熟实现）

不照搬：

- 过重的本地状态机与多层 Stage 裁决
- 用过度工程「捆死」模型能力

哲学差异一句话：

> **轻编排 · 章内工具 Agent · 摘要作记忆 · 结构作账本 · 图算法后处理。**

## 5. 功能需求

### 5.1 输入与格式优先级

| 优先级 | 格式 | 说明 |
|--------|------|------|
| **P0** | **EPUB** | 主路径；切章、元数据相对清晰 |
| P1 | MOBI / AZW | 可转 EPUB 或二期原生 |
| P2 | TXT | **非优先**；仅兼容「纯文本稿」场景 |
| 更后 | PDF | 排版与扫描噪声大 |

导入后内部统一为：

```text
书元数据 + 章节列表（id / 标题 / 顺序 / 正文）
```

### 5.2 主流程（两遍 + 汇总）

```text
上传 EPUB
    ↓
解析为章节列表
    ↓
【可选·辅助】Cast Pass：NLP 全书扫人名候选 → 人名册草稿
    · 与章间记忆同类：辅助对齐，非出图主路径
    · 长篇人物爆炸时价值更大；中短篇可弱化/后置
    ↓
【主路径】按章分析（可并行）+ 收尾归纳
    · 传入：章 id、人名册（可有可无）、（长篇可选）前文总结
    · Agent 用工具：取该章正文、搜索/grep 原文
    · 产出：本章 JSON（人物/关系/事件/证据）+ 本章短总结
    · 可回写：新别名进人名册
    · 章少量大：全章并行后终局检查/归纳（见架构双模式）
    ↓
【汇总出图】
    · 合并多章账本（真正大规模影响出图质量的是章内提取 + 归纳 + 过滤）
    · 软硬权重 + 出现次数等过滤
    · 支持「仅前 N 章」防剧透视图
    ↓
交互图谱 + 导出
```

### 5.3 人名册（Cast）

**目标：** 尽量先对齐「书里有谁、都怎么叫」，再抽关系。  
**定位：** 人名册与 Cast Pass 为**辅助**；无完整第 0 遍时，章分析仍可登记人物并出图。规划实现为 **NLP 全书扫描**（快、糙），见范围 §8：二期优先服务长篇。

最低字段（示意）：

| 字段 | 说明 |
|------|------|
| 正式名（canonical） | 图上主显示名 |
| 别名列表 | 外号、字号、称呼 |
| 简介一句 | 可选，如「贾府嫡孙」 |
| 性别 | 可选：男/女/未知；用于头像框模式配色区分 |
| 重要度粗标 | 可选：主/配/龙套（可后算）；用于头像尺寸/透明度区分 |

规则：

- 第 0 遍允许粗糙，后续章分析可增补别名与新人
- 分析章时优先映射到人名册正式名
- **疑似同人**进「待合并」队列，不默认静默合并错人
- 不强制每章都跑「别名子 Agent」；合并是偶发补丁，主路径是**维护通讯录**

### 5.4 章级分析（工具 Agent）

**触发：** 传入 `chapter_id`（或批量到第 N 章）。

**建议工具（思路级）：**

| 工具 | 作用 |
|------|------|
| 获取章节正文 | 按 id 取文，可分段 |
| 章内搜索 / grep | 按人名、关键词取证 |
| 查人名册 | 对齐正式名与别名 |
| 登记/更新人物 | 新人、新别名（受校验） |
| 提交本章结果 | 写入结构化章 JSON（校验后） |

**本章产出：**

1. **章 JSON（账本）**  
   - 本章涉及人物（尽量正式名 + 本章别名）  
   - 关系记录（见下节，支持多条、多类型）  
   - 事件（可选，便于解释）  
   - 每条关系尽量带：章节号、说明、**原文短句**
2. **章总结（记忆）**  
   - 短段落，供后续章使用  
   - 总结过长 → 压缩为**大总结**；之后上下文以大总结 + 最近若干章细总结为主

**记忆策略：**

```text
分析第 k 章的上下文 ≈
  大总结（若有）
  + 最近 r 章细总结
  + 人名册（或主名单摘要）
```

### 5.5 关系模型：多标签 + 软硬权重

#### 原则

1. A 与 B 的关系是 **标签集合**，不是单选一  
2. 一章写「朋友」、一章写「师徒」、一章写「夫妻」——**都可入账**  
3. **硬关系之间不互相覆盖**（师徒与夫妻可并存）  
4. **软关系可被硬关系在展示上压制**（账本仍保留，默认折进「更多」）  
5. 「覆盖」只影响**展示优先级**，不删历史记录  

#### 硬度分档（可配置，示意）

| 档 | 示例类型 | 规则 |
|----|----------|------|
| **硬** | 夫妻、亲子、兄妹、师徒 | 并列展示；互不覆盖 |
| **中** | 主仆、上下级、同门、结盟 | 可并存；展示次于硬 |
| **软** | 朋友、相识、同场等 | 易泛滥；有硬关系时默认弱化显示 |

类型表：首期 **短枚举**（可控数量），每项带 `soft | mid | hard`（或数值权重）。  
软类型宜粗（一个「朋友」即可），硬类型宜稳（夫妻/亲子/师徒分开）。

#### 账本中的边（逻辑结构）

```text
A ↔ B
  tags:
    - type: 师徒, tier: hard, chapters: [...], evidences: [...]
    - type: 夫妻, tier: hard, chapters: [...], evidences: [...]
    - type: 朋友, tier: soft, chapters: [...], evidences: [...]
  默认展示: [师徒, 夫妻]   // 朋友折叠到「更多」
```

汇总键：`(人物A, 人物B, type)` 合并章节列表与证据列表。

#### 展示用强度（第 7 关，汇总算）

示意：

```text
分数 ≈ 类型基础分（硬 > 中 > 软）
      + 出现章数 × 系数
      + 有合格证据的加分
```

用于排序、默认过滤、弱软线隐藏；**禁止**用分数让「夫妻」删掉「师徒」。

### 5.6 证据（可解释）

每条关系记录尽量包含：

| 字段 | 说明 |
|------|------|
| chapter_id | 哪一章 |
| quote | 原文短句（一两句） |
| note | 一句话说明（可选） |

**最低准入（可配置）：**

- MVP：有章节 + 非空说明；鼓励有 quote  
- 加强：quote 必须能在该章正文中匹配到（搜得到才收）

工具 Agent 路径：优先 **搜索到原文再摘录**，减少凭空编证据。

### 5.7 汇总与出图

**输入：** 已选章节范围的章 JSON 集合（全书或前 N 章）。

**步骤：**

1. 人名以人名册对齐  
2. 按 `(A,B,type)` 合并  
3. 算展示分、应用软硬显示规则  
4. 过滤过弱边 / 过路人（规则可调，见 5.7.6）  
5. 生成图数据 → 前端展示  

**防剧透：**

```text
用户设定「读到第 N 章」
→ 只使用 chapter_order ≤ N 的账本切片出图
```

**视图（长篇更重要）：**

- 默认核心人物子图  
- 以某人为中心的邻域  
- 按关系类型筛选（只看血缘 / 只看硬关系）  
- 展开「更多」见被压制的软关系  

#### 5.7.1 章节范围筛选（防剧透切片 UI）

用户在前端可直接控制「读到第几章」，图实时重算：

| 交互 | 说明 |
|------|------|
| 章节滑块 / 输入框 | 拖动或输入 N，仅汇总 `chapter_order ≤ N` 的账本切片 |
| 快捷按钮 | 「全书」「前 1/4」「前半」等预设 |
| 实时反馈 | 调整后图上节点/边即时增减；被切掉的部分不渲染（不灰显，避免暗示） |
| 章节标题预览 | 滑块旁显示当前 N 对应的章节标题，方便定位进度 |

#### 5.7.2 渲染样式：纯文字模式

适合快速浏览、文字为主的场景，不依赖头像资源：

```
  ┌──────────┐         师徒          ┌──────────┐
  │  唐僧     │ ──────────────────▶  │  孙悟空   │
  └──────────┘                       └──────────┘
                                        │
                                   夫妻  │
                                        ▼
                                    ┌──────────┐
                                    │  紫霞     │
                                    └──────────┘
```

| 要素 | 说明 |
|------|------|
| 节点 | 人物正式名，纯文字标签；可显示别名（小字） |
| 边 | 带箭头线条，线上标注关系类型（师徒/夫妻/朋友…） |
| 线条样式 | 硬关系实线、中关系虚线、软关系点线；可配置是否显示软关系 |
| 箭头方向 | 无向关系用双向箭头或无箭头；有向关系（如单恋）用单向箭头 |
| 布局 | 力导向（Force-directed）；节点可拖拽 |
| Hover | 高亮该节点的所有邻边；显示关系详情浮窗（类型 + 章 + 证据短句） |

#### 5.7.3 渲染样式：头像框模式

在文字模式基础上叠加视觉区分，信息密度更高：

| 要素 | 说明 |
|------|------|
| 头像来源 | 优先用户上传；其次 AI 生成的占位头像（首期可文字首字母色块占位） |
| 性别区分 | 头像框颜色区分：男蓝框 / 女粉框 / 未知灰框（可配置色板） |
| 框形状 | 圆形（默认）；可选方形等 |
| 重要度区分 | 主角头像更大 / 配角中等 / 龙套小号并半透明 |
| 边样式 | 同文字模式的线型规则；关系标签悬浮在连线中点 |
| 组合展示 | 同一对人物的多条关系标签堆叠显示，可展开「+N」 |

视觉示意：

```
     ╭───╮         师徒          ╭───╮
     │ 👤 │  ═══════════════▶   │ 🐵 │
     │唐僧│ （蓝框·主角）        │悟空│ （蓝框·主角）
     ╰───╯                     ╰───╯
                                  │
                            夫妻  ┊
                                  ▼
                              ╭───╮
                              │ 💜 │
                              │紫霞│ （粉框·配角）
                              ╰───╯
```

两种模式可一键切换，共享同一份图数据与布局。

#### 5.7.4 人物聚焦模式

选中某个人物后，图自动收缩为以该人物为中心的关系网络，方便快速理清一个人的所有关系。

**触发方式：**

- 点击节点选中 → 进入聚焦模式
- 搜索框输入人名 → 自动选中并聚焦
- 再次点击选中节点 / 点击空白处 / 点击「退出聚焦」按钮 → 退出

**聚焦效果：**

| 要素 | 说明 |
|------|------|
| 中心节点 | 被选中人物放大居中，高亮强调 |
| 一度关系 | 与中心人物有直接关系的节点保留，正常渲染 |
| 无关节点 | 与中心人物无直接关系的节点淡出隐藏（非删除，可一键恢复全局视图） |
| 边过滤 | 仅保留中心人物相关的边；其余边不渲染 |
| 关系标签 | 中心人物的所有关系类型列在侧边栏，可逐条勾选筛选（只看师徒/只看血缘…） |

**侧边栏信息面板（聚焦时）：**

```
┌─────────────────────────┐
│  ◎ 唐僧                  │
│  ─────────────────────  │
│  性别：男  重要度：主角    │
│  别名：玄奘、御弟         │
│  ─────────────────────  │
│  关系网络 (5)            │
│  ☑ 师徒 → 孙悟空   hard  │
│  ☑ 师徒 → 猪八戒   hard  │
│  ☑ 师徒 → 沙悟净   hard  │
│  ☐ 朋友 → 孙悟空   soft  │
│  ☑ 敌对 → 白骨精   mid   │
│  ─────────────────────  │
│  [展开二级] [退出聚焦]    │
└─────────────────────────┘
```

**与章节筛选联动：**

聚焦模式与 5.7.1 的章节范围筛选叠加生效——先切前 N 章，再聚焦某人物，只看到该人物在前 N 章内的关系网络，双重防剧透。

**与渲染样式联动：**

聚焦模式与纯文字 / 头像框两种渲染样式完全兼容，切换渲染样式不影响聚焦状态。

#### 5.7.5 导出

| 格式 | 说明 |
|------|------|
| **PNG** | 导出当前画布为图片；包含当前章节范围、渲染样式、图例水印 |
| **SVG** | 矢量导出，方便二次编辑/缩放（首期可选） |
| JSON | 导出当前切片的图数据（节点 + 边 + 证据），可重新导入 |
| Mermaid | 生成 Mermaid 代码片段，可贴到支持 Mermaid 的平台（后置） |

导出时：
- 自带图例（关系类型 → 线型 / 颜色对应表）
- 自带「前 N 章」标注，防止脱离上下文误读
- 头像模式导出时内嵌头像图片（不依赖外部链接）

#### 5.7.6 人物过滤（默认去路人）

长篇人物众多，不做过滤会变成「糊墙海报」（见反例）。默认过滤只出现极少数章节的「路人」，让图聚焦于有实际戏份的人物。

**出现次数的定义：**

采用**按章计（chapter_appearance_count）**：人物在某章的「涉及人物」列表中出现，计 1 次；同一章内提及多次仍计 1。

| 方案 | 计什么 | 取/舍 |
|------|--------|-------|
| **A. 按章计（采用）** | 章级分析产出的「涉及人物」列表中出现 = 1 次 | 与 5.4 天然对齐，零额外成本；防剧透切片时计数自动跟随前 N 章；稳定可复现 |
| B. 按原文提及计 | grep 全文统计名字/别名出现次数 | 更精确但别名匹配易漏；长章节天然次数高；增加分析成本 |
| C. 按有关系记录的章数 | 只统计有关系的章节数 | 与图上边直接关联，但无关系的独立出场会被完全丢弃 |

选 A 的理由：数据来源于章级分析已有产出，不需要额外计算；切换章节范围时计数自动重算（前 N 章内该人物出现在几章），与 5.7.1 的切片天然联动。

**过滤 UI：**

| 交互 | 说明 |
|------|------|
| 滑块 | 「最少出现 N 章」可调，默认值 = 2（过滤只出现 1 章的过路人） |
| 显示被过滤数 | 如「已隐藏 87 个路人角色」，点击可展开查看被过滤名单 |
| 例外保留 | 即使低于阈值，若人物有 hard 关系（如夫妻/亲子），仍保留——硬关系本身说明有剧情分量 |
| 与章节切片联动 | 切前 N 章后，出现次数自动按前 N 章重算，阈值滑块不变 |
| 与聚焦模式联动 | 聚焦某人时，被聚焦人物无视过滤阈值强制显示（用户主动选的人不应被隐藏） |

**阈值不写死的理由：** 不同书人物密度差异大，《红楼梦》可能有上百人物，《动物农场》只有十几个。固定阈值 2 对短书太松、对长书可能太紧。因此提供滑块让用户自行微调，默认值 2 仅作为起步建议。

### 5.8 人工校对（必要闭环）

- 编辑人名册（合并、改正式名、别名）  
- 增删改关系标签  
- 重跑单章分析  
- 调整「前 N 章」与过滤阈值  

自动结果默认是草稿，**可改**才是产品。

## 6. 约束策略（薄版本）

对照重型方案，ZhiYing 只保留「划算」的约束：

| 项 | 做法 |
|----|------|
| 关系类型 | 短枚举 + 软中硬标记 |
| 结构校验 | 强类型 / 提交工具参数校验（必做，不讨论） |
| 类型词大表归一 | **不做** GEN 式厚映射；靠枚举参数直接失败重试 |
| 别名 | **人名册为主**，待合并队列为辅 |
| 前文 | 章总结 + 大总结压缩 |
| 证据 | 章 + 原文；可升级为「正文可匹配」 |
| 上图硬度 | 汇总时类型权重 + 出现次数等 |

## 7. 与「纯 Prompt 流水线 / 重状态机」的差异

| 维度 | 重流水线代表思路 | ZhiYing |
|------|------------------|-----------|
| 章内 | 整章塞 prompt 填大 JSON | **工具 Agent** 按需读、搜、写回 |
| 章间记忆 | 重结构化 state | **总结链 + 人名册 + 章 JSON** |
| 约束厚度 | 多层门控、长代码路径 | 薄约束，出口紧、过程松 |
| 关系 | 易做成单一类型演进 | **多标签 + 软硬展示** |
| 防剧透 | 能做非主打 | **前 N 章切片** 一等公民 |
| 出图 | 自研量化过滤 | **可后置借鉴**，不阻塞 MVP |

Agent 用在刀刃上：**取证、补漏、按章写入**；  
全书遍历与出图过滤仍由**编排**保证覆盖与可控。

## 8. 范围划分与实现顺序

**原则：** 质量与体验的大头在 **章内提取 + 收尾归纳 + 可读出图**。  
Cast Pass（NLP 全局人名扫）与章间记忆同属 **辅助层**——书越长、人越多，边际价值越大，故放到服务长篇的二期，不堵一期中篇闭环。

### 8.1 一期（P0）：基础 + 中篇够用的分析闭环 + 文字图谱

按依赖顺序推进：

#### A. 基础骨架

- [ ] 工程脚手架（前后端、配置、workspace 落盘；**本机个人，不做 jail/catalog/jobs 框架**）
- [ ] 薄错误处理 + **关系枚举 SSOT**（prompt/校验同一份）
- [ ] **LLM Provider** 可配置（OpenAI 兼容；经 LangChain ChatModel）
- [ ] EPUB 导入与切章 → 统一章节列表
- [ ] 书籍元数据 / 分析状态（扫 workspace 列书即可）
- [ ] 基础 REST + 分析进度（SSE）

#### B. 章分析主路径（中篇优先）

- [ ] 章级工具 Agent（**LangChain**：提示词模板 + 工具注解 + tool loop）：读章、grep、提交章 JSON（人物/关系/证据）
- [ ] 多标签关系 + 软硬展示规则（汇总时应用）
- [ ] **短章/中篇：多章并行 + 终局归纳**（`few_long`：无章间记忆全并行 → 确定性合并 → Check/Merge Agent）
- [ ] 人名册：分析中可增补；**人工可编辑**（正式名/别名）；不依赖完整 Cast Pass
- [ ] 单章 / 批量至第 N 章；章结果缓存可重跑
- [ ] Aggregator：合并账本 + 前 N 章防剧透切片

> 一期可不做：NLP Cast Pass、章间记忆链 / 大总结压缩、长篇波次调度打磨。

#### C. 前端（一期就要能演示、好看）

- [ ] **纯文字节点**图谱（力导向、可拖拽；默认主样式）
- [ ] 简单好看的布局与交互（hover 关系详情：类型 + 章 + 证据短句）
- [ ] **人物聚焦**（选中 → 一度关系网络 + 侧边栏勾选筛选）
- [ ] **按出现频率（章数）过滤**路人（阈值滑块，默认隐藏仅 1 章等）
- [ ] 前 N 章滑块（防剧透，与汇总联动）
- [ ] **导出**：PNG + JSON（图例 / 前 N 章标注尽量带上）
- [ ] 书籍上传、分析进度、人名册基础编辑

**一期明确后置（不做完也能演示）：**

- 头像框渲染模式  
- NLP 全书 Cast Pass  
- 章间记忆 / 波次并行长篇优化  
- Mermaid 导出、SVG 等可再延  

### 8.2 二期（P1）：长篇辅助 + 体验加深

书越长、人物越多，下列辅助价值越大：

- [ ] **Cast Pass（NLP 全书扫描）**：人名候选 + 频次/粗别名 → 人名册草稿（辅助，允许糙）
- [ ] **章间记忆**：章总结链 + 大总结压缩；**many_chapters 波次并行**时注入 MemorySnapshot
- [ ] 长篇默认视图与类型筛选打磨  
- [ ] 人名待合并工作流  
- [ ] 证据 quote 正文可匹配（加强）  
- [ ] 断点续跑、成本/进度（token/章）展示  
- [ ] **头像框模式**（性别框色 / 重要度尺寸；首期可用字色块）  

### 8.3 三期及更后（P2+）

**工程硬化（本机个人默认不做；真痛再做）：** path jail、全局书目索引、jobs 任务框架、request_id/health 等——见架构 §2.2.3 / §13.3。

产品向更后：

- [ ] MOBI（或转 EPUB）、TXT/PDF  
- [ ] 关系时间轴动画  
- [ ] 自然语言改图  
- [ ] 本地模型 / 私有化  
- [ ] 中篇「一键全景」体验优化包

## 9. 非功能需求

| 类 | 要求 |
|----|------|
| 成本 | 单章工具步数上限；可配置模型；缓存章结果避免重复烧钱 |

| 隐私 | 用户书籍默认本地/私有；不拿用户书训练（产品承诺层） |
| 合规 | 个人分析用途；不提供盗版书源；分享注意剧透与版权 |
| 性能 | 长篇允许数十分钟级整书；需进度与可中断 |

## 10. 成功标准（感觉用）

一期成功不看「一次全对」，而看：

1. 中篇（或少章书）跑通：**上传 → 并行章分析 → 归纳 → 出图**  
2. 打开图**默认能读**（频次过滤生效），不是密网  
3. 点开一条关系能看到**哪一章、哪句依据**（有则强信任）  
4. 聚焦某人能看清其关系网；导出 PNG/JSON 可用  
5. 人名册可改；用户愿意修几处而不是整单扔掉  
6. （加分）设「读到第 N 章」后无明显后文剧透边
