| 项 | 内容 |
|----|------|
| 产品名 | **ZhiYing** |
| 一句话 | 上传电子书，自动生成准确、可读、可解释的人物关系图 |
| 文档性质 | PRD v1.0 |
| 日期 | 2026-10-05 |
| 状态 | 产品目标 SSOT |
| 范围 | 只写做什么、给谁、用户可见的行为与范围；系统怎么做见 [DESIGN](./DESIGN.md) |

---

## 1. 背景与问题

读中长篇小说时，人物多、称呼乱、关系随章节变化。读者往往只能：

- 手工画思维导图
- 把摘要丢给通用 AI 生成关系图
- 网上搜别人画的图（易剧透、不准）

市面缺少一套顺畅的体验：

> **上传书 → 自动出人物关系 → 可读、可解释 → 浏览与导出**

一期提供章节聚焦（单章视图与前 N 章累计视图），方便边读边查；严格的按阅读进度防剧透作为二期候选特色功能，当前不作为核心闭环与验收要求。

现有开源方案大多偏重状态机和多层门控，工程重、对模型约束极死。ZhiYing 走更轻的路线：过程交给 Agent 灵活处理，出口用结构和规则兜住质量。

## 2. 产品目标

### 2.1 要做成什么样

1. **主输入：EPUB**（主流电子书格式；TXT 仅作后续兼容）
2. **先建人名册，再抽关系**——减少同一个人裂成多个节点
3. **按章分析并汇总**；可按单章或前 N 章聚焦查看（§5.7.1），严格防剧透后置到二期候选
4. **关系多标签**——同一对人物可同时具备多种关系类型
5. **软关系兜底**——先找硬 / 中关系；无此类关系但有实际交流依据时考虑软关系。之前已有的软关系保留，默认可被强关系折叠；硬关系之间互不覆盖
6. **证据可解释**——关系尽量带来源章节与原文短句
7. **出图可过滤**——默认可读，不靠蜘蛛网硬撑「全量真实」
8. **势力 = 团体聚合**——学校、教会、组织、家族、阵营等均可，与关系边正交（见 §3.1）
9. **百人级大图以势力分区为主**——100+ 人仍要一张可读大图时，按势力分块最有效（见 §4.4）；过滤和聚焦是配套手段，不能替代分区

### 2.2 明确不做（现阶段）

- 不做成通用写作 IDE 或网文诊断台
- 不追求一次塞进整本长上下文「魔法出图」
- 不复刻现有方案的重状态机与多层裁决
- 不把 PDF / 扫描版放进首期
- 不默认做社交图谱社区（版权与剧透风险）
- 当前不承诺严格防剧透（人名、团体、关系演变随进度变化）；二期是否作为特色功能实施，另行确定
- 本期不做人工纠错，不要求用户判断人物身份、审核关系或修正团体归属
- 本期只做基础证据模式，不做加强模式及模式切换

## 3. 目标用户

| 用户 | 定位与诉求 |
|------|------|
| 尚未读过这本书的用户 | **核心用户**。无需预先了解情节与人物，即可得到系统自动生成、可理解的关系图 |
| 已读过书、主要为了画图的读者，读书会 / 自媒体 | 非核心用户，可浏览与导出；本期不围绕其手动校图诉求设计流程 |

核心用户缺少判断结果对错的知识。若系统必须依赖用户合并人物、补关系或逐项审核才能产出可用图，就没有完成核心任务。本期自动完成认人、关系判断、补查与出图；质量问题不能通过增加人工纠错步骤转交给用户。

未读过书的用户是当前定位；防剧透仍按既定决定后置，不因此重新纳入本期。
### 3.1 术语：什么叫「势力」

PRD 中的**「势力」**不是狭义的政治派系或正邪对立，而是：

> **人物所属的团体聚合（affiliation group）——一群人因共同机构、场景、组织身份或稳定归属而聚在一起。**

| 算势力 | 例子 |
|--------|------|
| 学校 / 年级阶段 | 小学、中学、大学 |
| 宗教 / 教会 | 某教堂、修会、神职圈子 |
| 组织 / 机构 | 公司、门派、军队、学院 |
| 家族 / 房支（作团体时） | 贾府、某世家（血缘细节仍由关系边表达） |
| 政治 / 对抗阵营 | 皇后党、叛军——只是势力的子类，不是定义本身 |
| 叙事世界 / 生活圈 | 成长小说里「某阶段的生活世界」 |

| 不算势力 | 说明 |
|----------|------|
| 两人间的关系类型 | 朋友、亲子、师徒 → 属于边 / 标签（见 §5.5） |
| 亲疏强弱 | 与主角的远近 → 属于边权重，不是团体 |
| 单次同场 | 无稳定团体身份，不自动升格为势力；能否作为软关系兜底还要看实际交流依据（§5.5） |

**与关系正交：**

- **势力**描述节点归属：人落在哪个团体块（可多归属）
- **关系**描述边：人与人之间的类型（朋友 / 师徒 / 亲子…）

同一对「朋友」可分属不同势力（小学朋友 vs 大学朋友）；同一个人可属多个势力（主角跨小学 / 中学 / 大学），布局上取主归属落块，次要归属用标记或放块交界。

## 4. 核心设计原则

### 4.1 中篇与长篇：两种体验，一套数据

| | 中篇（如《百年孤独》量级） | 长篇（如《红楼梦》量级） |
|--|---------------------------|--------------------------|
| 用户想要 | 一张读得懂的全景图 | 可导航的地图册，而非一张糊墙海报 |
| 默认展示 | 尽量展示主要人物与关系 | 按势力分块的大图 + 下钻 + 搜索 |
| 记忆与累计 | 较轻 | 按章入账；章间记忆属于后续辅助能力 |
| 章节聚焦 | 单章 / 前 N 章视图（§5.7.1） | 同左；长篇边读边查更依赖它 |
| 严格防剧透 | 二期候选特色功能 | 二期候选特色功能，当前不实施 |
| 布局主轴 | 人少时可用亲疏 / 力导向 | 势力分区优先（见 §4.4） |

两者共享同一套按章积累的数据，区别仅在展示策略与默认过滤。

### 4.2 过程松、出口紧

| 交给系统灵活处理 | 由规则严格约束 |
|------------------|----------------|
| 怎么读章、是否搜索原文 | 输出结构（人物 / 关系 / 事件字段） |
| 推理与摘证据 | 关系类型优先归入预定义类型库；罕见但重要的允许登记为书内新类型 |
| 本章小结怎么写 | 写入前校验；本期按基础证据条件准入 |
| | 人物 ID / 关系方向由系统校验；展示用软硬权重与出现次数过滤 |

不把模型当「随便写库的上帝」，也不把模型当「只会填死表的表格工」。

### 4.3 记忆与账本分离

| 概念 | 用途 |
|------|------|
| **章总结 / 大总结** | 给系统的工作记忆（情节上下文） |
| **人名册** | 认人、管理别名 |
| **章结果数据** | 事实账本（出图的主数据源） |

出图以账本为准，不以总结复述为准。
### 4.4 百人级大图：势力分区是主策略

产品目标包含：**人物过百时，关系图仍然可用**——不是只能看 20 人子集，也不是只能聚焦后才看懂。

布局手段的优先级：

| 优先级 | 手段 | 作用 |
|--------|------|------|
| **P0 主策略** | **按势力分区**（§3.1） | 把 100+ 人拆成可读的块；块内局部布局，块间靠桥接人物 |
| P1 配套 | 边过滤、软边降权、块内折叠 | 块内过密时的二级收敛 |
| P1 配套 | 聚焦 / 搜索 | 导航，不替代全局分块秩序；章节切片另列二期候选 |
| P2 辅视图 | 亲疏扇区、族谱、力导向 | 可切换的辅模式，不能作为 100+ 全景的唯一依赖 |

**为何必须是势力分区：**

1. 按关系类型分区装不下规模——同学 / 朋友会跨多个团体，挤在同一区域必然混乱
2. 纯力导向在百人网络上不可读——缺乏语义分块，没有「从哪看起」
3. 小说人物爆炸时，团体归属往往比「和主角第几档亲」更稳——一章一世界、一校一圈、一府一党
4. 边表达关系、块表达归属——两层正交后，百人图才同时具备结构与细节

> **结论：** 100 人以上仍可用的大关系图，默认骨架 = 势力分区。过滤与聚焦是必要配套，亲疏中心图是有价值的辅模式。

无清晰势力可抽时，应用共现 / 阶段等启发式仍产出分区（可命名为「第 N 阶段」等），而非退回百人单层布局；实在无法分块时降级为强过滤子集 + 辅布局，并在界面标明。

## 5. 功能需求

### 5.1 输入与格式优先级

| 优先级 | 格式 | 说明 |
|--------|------|------|
| **P0** | **EPUB** | 主路径；章节切分、元数据清晰 |
| P1 | MOBI / AZW | 可转 EPUB 或二期原生支持 |
| P2 | TXT | 仅兼容纯文本稿场景 |
| 更后 | PDF | 排版与扫描噪声大 |

导入后内部统一为：书元数据 + 章节列表（标题 / 顺序 / 正文）。

### 5.2 主流程

```text
上传 EPUB
    ↓
解析为章节列表
    ↓
【可选·辅助】全书扫描人名候选 → 人名册草稿
    · 辅助对齐，非出图主路径
    · 长篇人物多时价值更大；中短篇可弱化
    ↓
【主路径】按章分析 + 按需消歧与补查
    · 输入：章节、人名册（可有可无）、前文摘要（长篇可选）
    · 系统按需读取章节正文、搜索取证
    · 产出：本章结构化数据（人物 / 关系 / 事件 / 证据）+ 本章摘要
    · 可回写：新别名进人名册
    ↓
【汇总出图】
    · 合并多章数据，去重归一
    · 应用软硬权重 + 出现次数等过滤
    · 默认汇总全书已分析数据；可切到单章 / 前 N 章聚焦（§5.7.1）
    ↓
交互图谱 + 导出
```

### 5.3 人名册（Cast）

**目标：** 尽量先对齐「书里有谁、都怎么叫」，再抽关系。

**定位：** 人名册是辅助工具；无完整全书扫描时，章分析仍可登记人物并出图。

最低字段：

| 字段 | 说明 |
|------|------|
| 正式名 / 稳定称呼 | 图上主显示名；无姓名人物用原文可稳定识别的称呼，不编造姓名 |
| 别名列表 | 有原文依据的外号、字号、稳定称谓；不包含仅在某次上下文中成立的泛称 |
| 简介 | 重要人物必有，路人可空（见下方规则），如「贾府嫡孙」 |
| 性别 | 可选：男 / 女 / 未知；用于头像框配色 |
| 重要度 | 可选：主角 / 配角 / 龙套（可后算）；用于节点大小区分 |

规则：

- 首轮扫描允许粗糙，后续章分析可增补别名与新人物
- **无姓名但可稳定识别的具体人物也收录**，不以是否有专名作为准入条件；泛指群体、职业类别与无法区分具体人的称呼不因此自动成为人物
- **人物身份独立于名字**：关系关联具体人物；后续补充正式姓名或调整显示名，不改变人物及其关系的归属
- **别名归属主要在读章时完成**：结合正文和候选人物资料，判断新人或已有人物；新别名同时记录来源章节和归属理由，命中已有人物也不能漏掉新别名
- **名称只用于寻找候选，不直接证明同人**：允许同名或共享别名的不同人物，不因名称相同或首先匹配到某人就自动合并
- **稳定别名与本次指代分开**：“父亲”“师父”“那个老人”等称呼，先根据说话者和具体上下文确定本次指向；不能自动成为全书通用别名。只有原文支持稳定归属的称谓才作为人物别名展示
- **身份消歧由系统自动完成**：优先复用已有明确绑定；真正存在歧义时，结合相关人物资料及来源上下文做有限的针对性判断，不对所有名字重复审核
- 明确同一人的自动合并；信息不足时宁可暂时分开，也不要求用户逐项审核
- 本期不做人工合并 / 改名；身份归并由系统自动处理，不要求用户审核
- **重要人物必须有简介**：重要人物指出场 ≥ 2 章（阈值可配，与 §5.7.7 默认过滤一致）或有任一硬 / 中关系的人物。简介概括其在全书中的身份与经历，不只描述首次出场时的样子
- **路人不强求简介**：有就用首次出场章的介绍，没有可以留空

### 5.4 章级分析

**触发：** 指定章节（或批量到第 N 章）。

系统读章时可按需搜索原文取证、对照人名册认人、登记新人物与新别名。

**本章产出：**

1. **章数据（账本）**
   - 本章涉及人物（尽量正式名 + 本章别名）
   - 关系记录（支持多条、多类型）
   - 事件（可选，便于解释）
   - 每条关系尽量带：章节号、说明、原文短句
2. **章摘要（记忆）**：短段落，供后续章作情节上下文；长篇时压缩为大摘要（二期）

### 5.5 关系模型：多标签 + 软硬权重

#### 原则

1. A 与 B 的关系是**标签集合**，不是单选
2. 一章写「师徒」、一章写「夫妻」——都可入账
3. **硬关系之间互不覆盖**（师徒与夫妻可并存），硬+中、中+中 同理
4. **已有硬或中关系时，不再抽取新的软关系**——不为同一对人物重复补充低信息量标签
5. **软关系是一种兜底**：优先找硬 / 中关系；两人之间尚无这类关系、但有实际交流依据时，才考虑记录软关系。典型场景是某人物与主角有交流，却没有更明确的关系；不据此限定为只能连接主角
6. **之前已经记录的软关系保留**：后来发现硬 / 中关系时不删除旧记录，默认图折叠到「更多」
7. 兜底不等于无依据地补边，也不把一次告别、敬仰表达等情节描述直接命名为一种新关系；这些内容可作为判断关系的上下文或事件
8. **未决硬 / 中关系先留到后续判断**，不在未决阶段抢先生成替代软关系。候选经后续判断被否定后，若该人物对没有其他成立的硬 / 中关系，再由 AI 根据交流与上下文寻找有依据的兜底关系；不能把被否定的标签机械降级成软标签
9. 后续判断仍未决时，继续内部保留，不当作已否定来触发兜底；AI 找不到有依据的兜底关系时允许不连边
10. **最怕强关系被降成软关系，软标签本身不求精确。** 兜底时先查漏：交流与上下文显示的其实是硬 / 中关系（如长期教导、深厚友谊）时，作为强关系候选送补查，而不是贴软标签
11. **按出场章数区分重要人物与路人**（阈值与 §5.7.7 默认过滤一致，可配置）：人物对至少一端是重要人物时才做上述查漏；两端都是路人时只按交流依据贴最粗的软标签（如「相识」），不再细分，路人被漏掉也可接受，只需在人名册里有简短介绍

**关系与事件的边界：** 换个场景两人再见面，这个标签还成立吗？成立的是关系，只发生一次的是事件。事件不直接连边，只作交流依据。

| 样例 | 算关系 | 只算事件 |
|---|---|---|
| 精神引导 | 长期引导，文本赋予师长角色 → 师徒 / 师生 | 一次点拨性的谈话 |
| 技艺指导 | 反复、系统地传授 → 师生 | 一次指点 |
| 长期共同生活 | 稳定同行同住 → 同行；情谊深厚另加挚友 | 一起住过几天 |
| 一次援助 | 文本写成持续的恩情（如救命之恩被反复提起）→ 恩人 | 帮过一次忙 |
| 一起赴宴 | — | 有实际交流算交流依据；没有交流只是同章共现，不连边 |

#### 硬度分档（可配置）

| 档 | 示例类型 | 规则 |
|----|----------|------|
| **硬** | 夫妻、亲子、兄妹、师徒 | 并列展示；互不覆盖 |
| **中** | 主仆、上下级、同门、结盟、挚友 | 可并存；展示次于硬 |
| **软** | 朋友、相识、同场等粗粒度标签 | 有交流依据且该对无硬 / 中关系时作兜底；具体标签须与依据相符，不能从交流直接推成朋友 |

类型体系采用**半开放设计**：内置约 40～60 个高频类型，每项带软 / 中 / 硬属性；罕见但重要的关系允许登记为该书的新类型。

- 软类型宜粗（如「朋友」「相识」），不为每种交流行为另造标签；具体类型不得超出依据
- 文本明确写出的深厚友谊（挚友、知己、至交）属于中关系，由读章直接提交，不能只留给软兜底标成「朋友」
- 高频亲属关系应尽量精确：父亲 / 母亲、哥哥 / 弟弟 / 姐姐 / 妹妹、祖父母 / 外祖父母、堂表亲等
- 粗粒度标签（如「亲子」「兄弟姐妹」）只在原文信息不足时作为兜底

#### 汇总与方向

- 同一对人物的同一类型跨章合并，累积出现章节与证据
- 有向关系保留双方角色与方向，不能把 A → B 和 B → A 自动合成同一条无向关系

#### 展示强度

按硬度、出现章数、有无合格证据综合排序，用于默认过滤和弱化纯软边；**禁止**用强度让「夫妻」吞掉「师徒」。

### 5.6 证据（可解释）

每条关系记录尽量包含：

| 字段 | 说明 |
|------|------|
| 章节 | 出自哪一章 |
| 原文引用 | 原文短句（一两句） |
| 说明 | 一句话解释（本期基础模式必填） |

**本期准入：仅基础模式。**

- 有章节 + 非空说明；鼓励有原文引用，不以必须提供原文短句作为准入门槛
- 没有引文不自动否定关系；有引文时仍应校验其与正文一致，不能接受伪造摘录
- 加强模式（必须提供能在正文匹配的引文）后置，本期不提供模式切换

系统优先搜索到原文再摘录，减少凭空编造证据。

软关系也需要依据，但不要求原文直接出现「朋友」「相识」这样的标签；可依据实际交流及上下文判断。软 / 中 / 硬表示关系类型，不表示判断可信度。

**判断与补查：**

- 读章时的判断清晰、满足基础证据即可准入，不再对每条关系做全量复核
- 只对明确未决的硬 / 中关系做有限的自动补查；补查有上限，超时或预算耗尽不等于关系被否定
- 不做全书收尾统一校对；个别疑点未解决不阻塞其他合格关系出图

**未决关系的处理：** 默认图只展示已满足准入条件的关系。自动补查后仍无法确认的记录在内部保留，不伪装成已确认关系，也不要求用户逐项审核才能出图。

### 5.7 汇总与出图

**输入：** 当前已完成分析的数据集合；选了章节聚焦时只取对应章节范围（§5.7.1）。

**步骤：**

1. 人名以人名册对齐
2. 按（人物A, 人物B, 类型）合并
3. 计算展示分、应用软硬显示规则
4. 过滤过弱边 / 路人（规则可调，见 §5.7.7）
5. 生成图数据 → 前端展示

**视图（长篇更重要）：**

- 默认核心人物子图
- 以某人为中心的关系网络
- 按关系类型筛选（只看血缘 / 只看硬关系）
- 按势力分区浏览（见 §3.1、§5.7.5）
- 展开「更多」查看被压制的软关系

#### 5.7.1 章节聚焦

用于边读边查：读到某一章时，只看这一章有谁、他们之间是什么关系。默认仍是全书视图。

| 视图 | 人物 | 关系 |
|------|------|------|
| 全书（默认） | 全书人物，按 §5.7.7 过滤路人 | 全书已准入关系 |
| 第 N 章 | 只留第 N 章出场的人物；不按出场章数过滤路人（本章路人照常显示） | 这些人物之间、依据出现在第 N 章及以前的关系；依据在第 N 章的标为「本章」突出显示，更早确立的作为背景淡化显示 |
| 前 N 章（累计） | 第 1～N 章出场过的人物；出场章数只数前 N 章，再按 §5.7.7 过滤路人 | 依据出现在前 N 章内的关系 |

- 「出场」指人物出现在该章的人物列表里，含只被提及而未登场的人物
- 关系只显示前 N 章依据确立过的类型；详情里的章节与引文也只列前 N 章内的
- 单章 / 前 N 章视图的人物详情照常显示全书简介；单章视图另列此人在本章的关系依据与事件
- 类型 / 硬度筛选、人物聚焦、势力分区、导出在聚焦视图内照常可用；导出遵循所选范围并标注「第 N 章」或「前 N 章」
- 交互：章节选择器（输入或下拉，旁显示章节标题），可在全书 / 第 N 章 / 前 N 章之间切换，上一章 / 下一章快速翻动；被切掉的人物与关系不渲染（不灰显）
- 本功能**不是**防剧透保证：人物称呼、团体归属、重要度仍按全书结果；关系类型随剧情变化（如订婚→夫妻）不按进度重判。严格防剧透仍是二期候选

#### 5.7.2 渲染样式：纯文字模式

适合快速浏览、以文字为主的场景：

```
  ┌──────────┐         师徒          ┌──────────┐
  │  唐僧     │ ──────────────────▶  │  孙悟空   │
  └──────────┘                       └──────────┘
                                        │
                                   夫妻  │
                                        ▼
                                    ┌──────────┐
                                    │  紫霞     │
                                    └──────────┘
```

| 要素 | 说明 |
|------|------|
| 节点 | 人物正式名或稳定称呼；可显示别名（小字） |
| 边 | 带箭头线条，线上标注关系类型 |
| 线条样式 | 硬关系实线、中关系虚线、软关系点线 |
| 箭头方向 | 无向关系双向或无箭头；有向关系单向箭头 |
| 布局 | 用户可选多种布局（见 §5.7.5）；节点可拖拽 |
| 悬停 | 高亮该节点所有邻边；显示关系详情浮窗（类型 + 章节 + 说明，有引文时展示原文） |

#### 5.7.3 渲染样式：头像框模式

在文字模式基础上叠加视觉区分，信息密度更高：

| 要素 | 说明 |
|------|------|
| 头像来源 | 优先用户上传；其次系统生成的占位头像（首期可用首字母色块） |
| 性别区分 | 头像框颜色区分：男蓝 / 女粉 / 未知灰（色板可配） |
| 重要度区分 | 主角头像更大 / 配角中等 / 龙套小号并半透明 |
| 边样式 | 同文字模式；关系标签悬浮在连线中点 |
| 组合展示 | 同一对人物的多条关系标签堆叠显示，可展开「+N」 |

两种模式可一键切换，共享同一份图数据与布局。

#### 5.7.4 人物聚焦模式

选中某个人物后，图收缩为以该人物为中心的关系网络。

**触发方式：**

- 点击节点 → 进入聚焦
- 搜索框输入人名 → 自动选中并聚焦
- 再次点击 / 点击空白处 / 点击「退出聚焦」→ 退出

**聚焦效果：**

| 要素 | 说明 |
|------|------|
| 中心节点 | 被选中人物放大居中、高亮 |
| 一度关系 | 直接关系的节点保留，正常渲染 |
| 无关节点 | 淡出隐藏（非删除，可恢复全局视图） |
| 边过滤 | 仅保留中心人物相关的边 |
| 关系标签 | 所有关系类型列在侧边栏，可逐条勾选筛选 |

**侧边栏信息面板（聚焦时）：**

```
┌─────────────────────────┐
│  ◎ 唐僧                  │
│  ─────────────────────  │
│  性别：男  重要度：主角    │
│  别名：玄奘、御弟         │
│  ─────────────────────  │
│  关系网络 (5)            │
│  ☑ 师徒 → 孙悟空   硬    │
│  ☑ 师徒 → 猪八戒   硬    │
│  ☑ 师徒 → 沙悟净   硬    │
│  ☐ 朋友 → 孙悟空   软    │
│  ☑ 敌对 → 白骨精   中    │
│  ─────────────────────  │
│  [展开二级] [退出聚焦]    │
└─────────────────────────┘
```

**联动规则：**

- 二期若实施章节筛选，与聚焦叠加生效——先切前 N 章，再聚焦某人
- 与渲染样式完全兼容——切换纯文字 / 头像框不影响聚焦状态

#### 5.7.5 布局模式与势力分区

> 势力定义见 §3.1。硬原则见 §4.4。

##### A. 两层正交信息

| 层 | 表达什么 | 视觉表现 |
|----|----------|----------|
| **势力（归属）** | 人属于哪个团体 | 平面分区 / 色块 / 外框 |
| **关系（连边）** | 两人之间是什么 | 线型、标签、线粗 |

禁止把「朋友」当成势力名；朋友是边，学校 / 教会才是块。

##### B. 布局模式

| 模式 | 定位 | 说明 |
|------|------|------|
| **势力分区** | 大图默认 / 主策略 | 团体块聚拢，块间弱连或经桥接人；百人级全景首选 |
| 亲疏扇区（主角中心） | 辅模式 | 适合已裁子集或聚焦后；不宜单独扛 100+ 全景 |
| 族谱 / 代际 | 辅模式（可后置） | 家族史、血缘为主的书或块内下钻 |
| 网络总览 | 兜底 / 小图 | 力导向等；小规模场景 |

用户可切换布局，但产品默认与「大图可用」验收以势力分区为准。

##### C. 势力从哪里来

| 来源 | 说明 |
|------|------|
| 机构 / 场景实体 | 文中明确的学校、教会、门派、府邸名 |
| 共现 / 生活世界 | 同一阶段大量共现、跨阶段很少重叠 → 聚成「第 k 阶段」再命名 |
| 家族作团体 | 贾府等作为一个势力块；房支 / 辈分是块内结构 |
| 人工校正（后续可选，本期不做） | 用户改势力名、合并 / 拆分块、改归属不属于本期能力，也不是分区的必要流程 |

一人多势力：允许。布局取主势力落块，其余用徽章 / 次要色标记，或放块交界。

##### D. 与过滤、聚焦的关系

- 势力分区解决「百人怎么摆」；过滤解决「块内是否过密、路人是否该上图」——两者叠加，不是二选一
- 目标若是 100+ 可浏览大图：应分区优先，过滤阈值可放宽；若只做 20 人子集，则未验证大图能力
- 聚焦 / 搜索用于块内下钻与找人；全局秩序仍靠势力块
- 块内过密时：二级折叠或块内再筛，不退回取消分区

#### 5.7.6 导出

| 格式 | 说明 |
|------|------|
| **PNG** | 导出当前画布为图片；包含分析范围、渲染样式、图例水印 |
| **SVG** | 矢量导出，方便二次编辑（首期可选） |
| JSON | 导出当前图数据（节点 + 边 + 证据），可重新导入；遵循章节聚焦所选范围 |
| Mermaid | 生成 Mermaid 代码片段（后置） |

导出时：
- 自带图例（关系类型 → 线型 / 颜色对应表）
- 自带分析范围说明；章节聚焦时附「第 N 章」或「前 N 章」标注
- 头像模式导出时内嵌头像图片

#### 5.7.7 人物过滤（默认去路人）

长篇人物众多，不过滤会变成糊墙海报。默认过滤只出现极少数章节的路人，让图聚焦于有实际戏份的人物。

**出现次数的定义：**

采用**按章计数**：人物在某章的涉及人物列表中出现，计 1 次；同一章内提及多次仍计 1。

选择按章计数的理由：
- 与章级分析的产出天然对齐，无额外成本
- 计数来自本次汇总的数据；二期若实施章节切片，再按切片范围重算
- 稳定可复现

**过滤交互：**

| 交互 | 说明 |
|------|------|
| 滑块 | 「最少出现 N 章」可调，默认值 = 2 |
| 显示被过滤数 | 如「已隐藏 87 个路人角色」，可展开查看被过滤名单 |
| 例外保留 | 即使低于阈值，若人物有硬关系（如夫妻 / 亲子），仍保留 |
| 与章节切片联动（二期候选） | 切前 N 章后，出现次数自动按前 N 章重算 |
| 与聚焦联动 | 被聚焦人物无视阈值强制显示 |

阈值不写死：不同书人物密度差异大，固定值对短书太松、对长书可能太紧，因此提供滑块让用户自行微调。

### 5.8 自动完成与人工纠错边界

系统自动完成身份归并、关系归一、未决补查与异常处理，直接产出可用关系图。核心用户尚未读过书，没有能力承担事实校对；不能把人工纠错设计成正常流程、失败处理的必经步骤或质量兜底。

**本期不做：** 人工合并人物、改正式名 / 别名、增删改关系标签、修改势力与成员归属。此类能力留作后续可选方向，是否实施另行确定。

**本期保留：** 查看人名册、证据与分析进度，触发单章重跑，调整过滤阈值、聚焦、布局与导出。这些是查看与操作能力，不要求用户判定书中事实；重跑结果仍由系统自动处理。

### 5.9 失败、发布与用量

- **不发布有缺章的结果：** 整书分析中只要有章节最终读取失败，本次不发布新结果，用户看到的仍是上一版（首次分析则暂无图），并告知哪些章节失败、原因是什么。
- **失败可续跑：** 成功章节的结果保留；用户再次启动分析时只补读失败章节，不重复消耗已成功的章节。用户也可选择全部重读。
- **取消与重跑失败同样不发布：** 用户取消分析，或单章重跑失败时，上一版结果保持可读不变。
- **用量可见：** 前端展示本书分析累计消耗的 token（含输入 / 输出，整书分析与单章重跑合计），以及本次任务的消耗，便于估算成本。

### 5.10 删除书与清空分析

书架上每本书提供两个管理操作，都需用户二次确认，执行后不可恢复：

| 操作 | 结果 | 之后 |
|------|------|------|
| 删除书 | 书从书架消失，连同章节、全部分析结果与用量记录 | 要再分析须重新上传 |
| 清空分析 | 书与章节保留；关系图、各章分析结果、任务记录与累计用量全部清除，书回到「未分析」 | 再次分析从头读每一章，不沿用旧的章结果 |

- 书正在分析（含单章重跑）时两个操作都不可用，提示先停止分析。
- 正在查看的书被删除后，页面回到书架。

## 6. 范围划分与优先级

**原则：** 质量和体验的关键在于**章内提取 + 按需消歧与补查 + 可读出图**。全书人名扫描与章间记忆属于辅助层——书越长、人越多，边际价值越大，因此放到二期。章节聚焦一期提供；严格防剧透列为二期候选特色功能，是否实施另行确定。

**本期兼容边界：** 保留现有前端并适配本期功能；旧书籍都是测试数据，不要求迁移或兼容历史分析结果，可重新导入分析。现有评测集保留；保留数据不代表认可旧评分机制或沿用旧分数。

### 6.1 一期（P0）：中篇闭环 + 文字图谱 + 势力分区

#### A. 基础能力

- [ ] EPUB 导入与章节切分
- [ ] 人物关系类型库（预定义类型 + 书内新增）
- [ ] 模型可配置，支持多厂商切换
- [ ] 书籍管理、分析状态与进度展示

#### B. 分析

- [ ] 章级分析：读章、搜索取证、提交人物 / 关系 / 事件
- [ ] 自动身份消歧，用户无需逐项审核
- [ ] 全书关系归一，有向关系保留方向
- [ ] 多标签保留，默认图突出核心关系，弱关系折入「更多」
- [ ] 人名册自动增补并可查看，收录可稳定识别的无姓名人物
- [ ] 基础证据准入；未决强关系后续判断，被否定后再寻找有依据的兜底关系
- [ ] 单章 / 批量分析；章结果可缓存、可重跑
- [ ] 势力抽取与成员归属

#### C. 前端

- [ ] 纯文字节点图谱（可拖拽）
- [ ] 悬停查看关系详情（类型 + 章节 + 说明，有引文时展示原文）
- [ ] 人物聚焦（选中 → 一度关系网络 + 侧边栏筛选）
- [ ] 按出现频率过滤路人（阈值滑块）
- [ ] 势力分区布局（§4.4）
- [ ] 导出：PNG + JSON
- [ ] 书籍上传、分析进度、人名册查看
- [ ] 删除书、清空分析（§5.10）
- [ ] 本书分析累计 token 用量（§5.9）
- [ ] 章节聚焦：单章视图与前 N 章累计视图（§5.7.1）

**一期明确后置：** 人工纠错（人物合并 / 改名、关系编辑、势力修改）；加强证据模式；严格防剧透；头像框模式；全书人名扫描；章间记忆与长篇波次；Mermaid / SVG 导出；族谱布局。

### 6.2 二期（P1）：长篇辅助

- [ ] 候选特色功能：按阅读进度查看前 N 章关系图；是否实施另行确定

## 7. 非功能需求

| 类 | 要求 |
|----|------|
| 成本 | 单章分析步数有上限；可配置模型；缓存章结果避免重复消耗 |

| 隐私 | 用户书籍默认本地 / 私有；不用用户书做训练 |
| 合规 | 个人分析用途；不提供盗版书源；分享注意剧透与版权 |
| 性能 | 长篇允许数十分钟级整书分析；需进度展示与可中断 |

## 8. 成功标准

一期成功不看「一次全对」，而看：

1. 中篇跑通：上传 → 章分析 → 归纳 → 出图
2. 打开图默认能读（路人过滤生效），不是密网
3. 点开一条关系能看到来源章节与说明；有引用时可查看原文依据
4. 聚焦某人能看清其关系网；导出 PNG / JSON 可用
5. 未读过书的用户无需人工合并、校图或审核关系，也能直接得到可用结果

**量化质量目标待定。** 评测口径见 DESIGN §7；不沿用旧评测的综合分，也不把「90 分以上」作为已确认门禁。分数门槛等积累几次基线后再定，确定后写回本节。

**评测页（维护工具）：** 开发者在前端评测页选择评测集，可「重新分析并评测」（清空该书分析后整书重跑再评分），或只「评测当前结果」。页面展示总分与各项指标、逐章的漏检 / 误判及原因、未标注的结果，并能查看历史运行。旧后端的历史报告不在页面展示；没有运行记录时不编造分数。
