|----|------|
| 产品名 | **ZhiYing** |
| 一句话 | 上传电子书，自动生成准确、可读、可解释的人物关系图 |
| 文档性质 | PRD v1.14 |

## 1. 背景与问题

读中长篇小说时，人物多、称呼乱、关系随章节变化。读者往往只能：

- 手工画思维导图
- 把摘要丢给通用 AI 生成关系图
- 网上搜别人画的图（易剧透、不准）

市面缺少一套顺畅的体验：

> **上传书 → 自动出人物关系 → 可读、可解释 → 浏览与导出**

提供章节聚焦（单章视图与前 N 章累计视图），方便边读边查；不做严格的按阅读进度防剧透。

现有开源方案大多偏重状态机和多层门控，工程重、对模型约束极死。ZhiYing 走更轻的路线：过程交给 Agent 灵活处理，出口用结构和规则兜住质量。

## 2. 产品目标

### 2.1 要做成什么样

1. **输入：EPUB**（主流电子书格式）
2. **先建人名册，再抽关系**——减少同一个人裂成多个节点
3. **按章分析并汇总**；可按单章或前 N 章聚焦查看（§5.7.1）
4. **关系多标签**——同一对人物可同时具备多种关系类型
5. **软关系兜底**——先找硬 / 中关系；无此类关系但有实际交流依据时考虑软关系。之前已有的软关系保留，默认可被强关系折叠；硬关系之间互不覆盖
6. **证据可解释**——关系尽量带来源章节与原文短句
7. **出图可过滤**——默认可读，不靠蜘蛛网硬撑「全量真实」
8. **势力 = 团体聚合**——学校、教会、组织、家族、阵营等均可，与关系边正交（见 §3.1）
9. **百人级大图以势力分区为主**——100+ 人仍要一张可读大图时，按势力分块最有效（见 §4.4）；过滤和聚焦是配套手段，不能替代分区

### 2.2 明确不做

- 不做成通用写作 IDE 或网文诊断台
- 不追求一次塞进整本长上下文「魔法出图」
- 不支持 PDF / 扫描版
- 不默认做社交图谱社区（版权与剧透风险）
- 不承诺严格防剧透（人名、团体、关系演变随进度变化）
- 不做人工纠错，不要求用户判断人物身份、审核关系或修正团体归属
- 只做基础证据模式，不做加强模式及模式切换
- 不做支付、积分、付费档位；成本靠用量上限控制（§5.13）
- 不做头像框模式、SVG / Mermaid 导出
- 不做手机号或邮箱注册、自助找回密码；不做只发校验值、不上传文件的秒传

### 2.3 对外开放

1. **宣传期**：在小红书等平台发关系图，访客从官网或帖子里的链接直接打开示例书（§5.17），不用注册，用来看有没有人感兴趣
2. **内测期**：凭邀请码分批放号，用户上传自己的书。验证没读过书的读者愿不愿意用、看不看得懂，以及用户反馈能否沉淀为评测样本（§5.16）。不收费，按反馈和成本慢慢放号

## 3. 目标用户

| 用户 | 定位与诉求 |
|------|------|
| 尚未读过这本书的用户 | **核心用户**。无需预先了解情节与人物，即可得到系统自动生成、可理解的关系图 |
| 已读过书、主要为了画图的读者，读书会 / 自媒体 | 非核心用户，可浏览与导出；不围绕其手动校图诉求设计流程 |

核心用户缺少判断结果对错的知识。若系统必须依赖用户合并人物、补关系或逐项审核才能产出可用图，就没有完成核心任务。系统自动完成认人、关系判断、补查与出图；质量问题不能通过增加人工纠错步骤转交给用户。

### 3.1 术语：什么叫「势力」

PRD 中的**「势力」**不是狭义的政治派系或正邪对立，而是：

> **人物所属的团体聚合（affiliation group）——一群人因共同机构、场景、组织身份或稳定归属而聚在一起。**

| 算势力 | 例子 |
|--------|------|
| 学校 / 年级阶段 | 小学、中学、大学 |
| 宗教 / 教会 | 某教堂、修会、神职圈子 |
| 组织 / 机构 | 公司、门派、军队、学院 |
| 家族 / 房支（作团体时） | 贾府、某世家（血缘细节仍由关系边表达） |
| 政治 / 对抗阵营 | 皇后党、叛军——只是势力的子类，不是定义本身 |
| 叙事世界 / 生活圈 | 成长小说里「某阶段的生活世界」 |

| 不算势力 | 说明 |
|----------|------|
| 两人间的关系类型 | 朋友、亲子、师徒 → 属于边 / 标签（见 §5.5） |
| 亲疏强弱 | 与主角的远近 → 属于边权重，不是团体 |
| 单次同场 | 无稳定团体身份，不自动升格为势力；能否作为软关系兜底还要看实际交流依据（§5.5） |

**与关系正交：**

- **势力**描述节点归属：人落在哪个团体块（可多归属）
- **关系**描述边：人与人之间的类型（朋友 / 师徒 / 亲子…）

同一对「朋友」可分属不同势力（小学朋友 vs 大学朋友）；同一个人可属多个势力（主角跨小学 / 中学 / 大学），布局上取主归属落块，次要归属用标记或放块交界。

## 4. 核心设计原则

### 4.1 中篇与长篇：两种体验，一套数据

| | 中篇（如《百年孤独》量级） | 长篇（如《红楼梦》量级） |
|--|---------------------------|--------------------------|
| 用户想要 | 一张读得懂的全景图 | 可导航的地图册，而非一张糊墙海报 |
| 默认展示 | 尽量展示主要人物与关系 | 按势力分块的大图 + 下钻 + 搜索 |
| 记忆与累计 | 较轻 | 按章入账 |
| 章节聚焦 | 单章 / 前 N 章视图（§5.7.1） | 同左；长篇边读边查更依赖它 |
| 布局主轴 | 人少时可用亲疏 / 力导向 | 势力分区优先（见 §4.4） |

两者共享同一套按章积累的数据，区别仅在展示策略与默认过滤。

### 4.2 过程松、出口紧

| 交给系统灵活处理 | 由规则严格约束 |
|------------------|----------------|
| 怎么读章、是否搜索原文 | 输出结构（人物 / 关系 / 事件字段） |
| 推理与摘证据 | 关系类型优先归入预定义类型库；罕见但重要的允许登记为书内新类型 |
| 本章小结怎么写 | 写入前校验；按基础证据条件准入 |
| | 人物 ID / 关系方向由系统校验；展示用软硬权重与出现次数过滤 |

不把模型当「随便写库的上帝」，也不把模型当「只会填死表的表格工」。

### 4.3 记忆与账本分离

| 概念 | 用途 |
|------|------|
| **章摘要** | 给系统的工作记忆（情节上下文） |
| **人名册** | 认人、管理别名 |
| **章结果数据** | 事实账本（出图的主数据源） |

出图以账本为准，不以总结复述为准。
### 4.4 百人级大图：势力分区是主策略

产品目标包含：**人物过百时，关系图仍然可用**——不是只能看 20 人子集，也不是只能聚焦后才看懂。

布局手段的优先级：

| 优先级 | 手段 | 作用 |
|--------|------|------|
| **主策略** | **按势力分区**（§3.1） | 把 100+ 人拆成可读的块；块内局部布局，块间靠桥接人物 |
| 配套 | 边过滤、软边降权、块内折叠 | 块内过密时的二级收敛 |
| 配套 | 聚焦 / 搜索 / 章节聚焦 | 导航，不替代全局分块秩序 |
| 辅视图 | 亲疏扇区 | 可切换的辅模式，不能作为 100+ 全景的唯一依赖 |

**为何必须是势力分区：**

1. 按关系类型分区装不下规模——同学 / 朋友会跨多个团体，挤在同一区域必然混乱
2. 纯力导向在百人网络上不可读——缺乏语义分块，没有「从哪看起」
3. 小说人物爆炸时，团体归属往往比「和主角第几档亲」更稳——一章一世界、一校一圈、一府一党
4. 边表达关系、块表达归属——两层正交后，百人图才同时具备结构与细节

> **结论：** 100 人以上仍可用的大关系图，默认骨架 = 势力分区。过滤与聚焦是必要配套，亲疏中心图是有价值的辅模式。

无清晰势力可抽时，应用共现 / 阶段等启发式仍产出分区（可命名为「第 N 阶段」等），而非退回百人单层布局；实在无法分块时降级为强过滤子集 + 辅布局，并在界面标明。

## 5. 功能需求

### 5.1 输入格式

支持 **EPUB** 与 **TXT**。EPUB 按目录与章节标记切章；TXT 是网文读者最常见的格式：

| TXT 规则 | 说明 |
|------|------|
| 编码 | 自动识别常见中文编码（UTF-8、GBK 等），不要求用户转码 |
| 切章 | 内置多种常见分章方案（「第 X 章 / 回 / 节」、卷 + 章、数字序号、英文 Chapter 等，以及按长度分段），上传时自动选一种；都不适用时按长度分段，并告知用户 |
| 换方案 | 书详情显示当前分章方案；可改选其他方案，改选前能预览每种方案切出的章数与开头、中间、结尾几章的标题。已有分析结果时，改选会清空分析（先确认，已用额度不退还） |
| 秒传 | 同一个 TXT 文件且分章方案相同才命中（§5.14） |
| 书名 | 取文件名，去掉扩展名 |
| 不做 | 手动调整章节边界；用户自己写分章正则 |

导入后内部统一为：书元数据 + 章节列表（标题 / 顺序 / 正文）。

### 5.2 主流程

```text
上传 EPUB
    ↓
解析为章节列表
    ↓
按章分析 + 按需消歧与补查
    · 输入：章节、人名册
    · 系统按需读取章节正文、搜索取证
    · 产出：本章结构化数据（人物 / 关系 / 事件 / 证据）+ 本章摘要
    · 可回写：新别名进人名册
    ↓
【汇总出图】
    · 合并多章数据，去重归一
    · 应用软硬权重 + 出现次数等过滤
    · 默认汇总全书已分析数据；可切到单章 / 前 N 章聚焦（§5.7.1）
    ↓
交互图谱 + 导出
```

### 5.3 人名册（Cast）

**目标：** 尽量先对齐「书里有谁、都怎么叫」，再抽关系。

**定位：** 人名册是辅助工具；不做全书预扫描，人物由章分析登记。

最低字段：

| 字段 | 说明 |
|------|------|
| 正式名 / 稳定称呼 | 图上主显示名；无姓名人物用原文可稳定识别的称呼，不编造姓名 |
| 别名列表 | 有原文依据的外号、字号、稳定称谓；不包含仅在某次上下文中成立的泛称 |
| 简介 | 重要人物必有，路人可空（见下方规则），如「贾府嫡孙」 |
| 性别 | 可选：男 / 女 / 未知；在人物详情展示 |
| 重要度 | 可选：主角 / 配角 / 龙套（可后算）；用于节点大小区分 |

规则：

- 后续章分析可增补别名与新人物
- **无姓名但可稳定识别的具体人物也收录**，不以是否有专名作为准入条件；泛指群体、职业类别与无法区分具体人的称呼不因此自动成为人物
- **人物身份独立于名字**：关系关联具体人物；后续补充正式姓名或调整显示名，不改变人物及其关系的归属
- **别名归属主要在读章时完成**：结合正文和候选人物资料，判断新人或已有人物；新别名同时记录来源章节和归属理由，命中已有人物也不能漏掉新别名
- **名称只用于寻找候选，不直接证明同人**：允许同名或共享别名的不同人物，不因名称相同或首先匹配到某人就自动合并
- **稳定别名与本次指代分开**：“父亲”“师父”“那个老人”等称呼，先根据说话者和具体上下文确定本次指向；不能自动成为全书通用别名。只有原文支持稳定归属的称谓才作为人物别名展示
- **身份消歧由系统自动完成**：优先复用已有明确绑定；真正存在歧义时，结合相关人物资料及来源上下文做有限的针对性判断，不对所有名字重复审核
- 明确同一人的自动合并；信息不足时宁可暂时分开，也不要求用户逐项审核
- 不做人工合并 / 改名；身份归并由系统自动处理，不要求用户审核
- **重要人物必须有简介**：重要人物指出场 ≥ 2 章（阈值可配，与 §5.7.6 默认过滤一致）或有任一硬 / 中关系的人物。简介概括其在全书中的身份与经历，不只描述首次出场时的样子
- **路人不强求简介**：有就用首次出场章的介绍，没有可以留空

### 5.4 章级分析

**触发：** 指定章节（或批量到第 N 章）。

系统读章时可按需搜索原文取证、对照人名册认人、登记新人物与新别名。

**本章产出：**

1. **章数据（账本）**
   - 本章涉及人物（尽量正式名 + 本章别名）
   - 关系记录（支持多条、多类型）
   - 事件（可选，便于解释）
   - 每条关系尽量带：章节号、说明、原文短句
2. **章摘要（记忆）**：短段落，作为情节上下文（如团体归纳），不作为关系来源

### 5.5 关系模型：多标签 + 软硬权重

#### 原则

1. A 与 B 的关系是**标签集合**，不是单选
2. 一章写「师徒」、一章写「夫妻」——都可入账
3. **硬关系之间互不覆盖**（师徒与夫妻可并存），硬+中、中+中 同理
4. **已有硬或中关系时，不再抽取新的软关系**——不为同一对人物重复补充低信息量标签
5. **软关系是一种兜底**：优先找硬 / 中关系；两人之间尚无这类关系、但有实际交流依据时，才考虑记录软关系。典型场景是某人物与主角有交流，却没有更明确的关系；不据此限定为只能连接主角
6. **之前已经记录的软关系保留**：后来发现硬 / 中关系时不删除旧记录，默认图折叠到「更多」
7. 兜底不等于无依据地补边，也不把一次告别、敬仰表达等情节描述直接命名为一种新关系；这些内容可作为判断关系的上下文或事件
8. **未决硬 / 中关系先留到后续判断**，不在未决阶段抢先生成替代软关系。候选经后续判断被否定后，若该人物对没有其他成立的硬 / 中关系，再由 AI 根据交流与上下文寻找有依据的兜底关系；不能把被否定的标签机械降级成软标签
9. 后续判断仍未决时，继续内部保留，不当作已否定来触发兜底；AI 找不到有依据的兜底关系时允许不连边
10. **最怕强关系被降成软关系，软标签本身不求精确。** 兜底时先查漏：交流与上下文显示的其实是硬 / 中关系（如长期教导、深厚友谊）时，作为强关系候选送补查，而不是贴软标签
11. **按出场章数区分重要人物与路人**（阈值与 §5.7.6 默认过滤一致，可配置）：人物对至少一端是重要人物时才做上述查漏；两端都是路人时只按交流依据贴最粗的软标签（如「相识」），不再细分，路人被漏掉也可接受，只需在人名册里有简短介绍

**关系与事件的边界：** 换个场景两人再见面，这个标签还成立吗？成立的是关系，只发生一次的是事件。事件不直接连边，只作交流依据。

| 样例 | 算关系 | 只算事件 |
|---|---|---|
| 精神引导 | 长期引导，文本赋予师长角色 → 师徒 / 师生 | 一次点拨性的谈话 |
| 技艺指导 | 反复、系统地传授 → 师生 | 一次指点 |
| 长期共同生活 | 稳定同行同住 → 同行；情谊深厚另加挚友 | 一起住过几天 |
| 一次援助 | 文本写成持续的恩情（如救命之恩被反复提起）→ 恩人 | 帮过一次忙 |
| 一起赴宴 | — | 有实际交流算交流依据；没有交流只是同章共现，不连边 |

#### 硬度分档（可配置）

| 档 | 示例类型 | 规则 |
|----|----------|------|
| **硬** | 夫妻、亲子、兄妹、师徒 | 并列展示；互不覆盖 |
| **中** | 主仆、上下级、同门、结盟、挚友 | 可并存；展示次于硬 |
| **软** | 朋友、相识、同场等粗粒度标签 | 有交流依据且该对无硬 / 中关系时作兜底；具体标签须与依据相符，不能从交流直接推成朋友 |

类型体系采用**半开放设计**：内置约 40～60 个高频类型，每项带软 / 中 / 硬属性；罕见但重要的关系允许登记为该书的新类型。

- 软类型宜粗（如「朋友」「相识」），不为每种交流行为另造标签；具体类型不得超出依据
- 文本明确写出的深厚友谊（挚友、知己、至交）属于中关系，由读章直接提交，不能只留给软兜底标成「朋友」
- 高频亲属关系应尽量精确：父亲 / 母亲、哥哥 / 弟弟 / 姐姐 / 妹妹、祖父母 / 外祖父母、堂表亲等
- 粗粒度标签（如「亲子」「兄弟姐妹」）只在原文信息不足时作为兜底

#### 汇总与方向

- 同一对人物的同一类型跨章合并，累积出现章节与证据
- 有向关系保留双方角色与方向，不能把 A → B 和 B → A 自动合成同一条无向关系

#### 展示强度

按硬度、出现章数、有无合格证据综合排序，用于默认过滤和弱化纯软边；**禁止**用强度让「夫妻」吞掉「师徒」。

### 5.6 证据（可解释）

每条关系记录尽量包含：

| 字段 | 说明 |
|------|------|
| 章节 | 出自哪一章 |
| 原文引用 | 原文短句（一两句） |
| 说明 | 一句话解释（基础模式必填） |

**准入：仅基础模式。**

- 有章节 + 非空说明；鼓励有原文引用，不以必须提供原文短句作为准入门槛
- 没有引文不自动否定关系；有引文时仍应校验其与正文一致，不能接受伪造摘录
- 不提供加强模式（必须提供能在正文匹配的引文）及模式切换

系统优先搜索到原文再摘录，减少凭空编造证据。

软关系也需要依据，但不要求原文直接出现「朋友」「相识」这样的标签；可依据实际交流及上下文判断。软 / 中 / 硬表示关系类型，不表示判断可信度。

**判断与补查：**

- 读章时的判断清晰、满足基础证据即可准入，不再对每条关系做全量复核
- 只对明确未决的硬 / 中关系做有限的自动补查；补查有上限，超时或预算耗尽不等于关系被否定
- 不做全书收尾统一校对；个别疑点未解决不阻塞其他合格关系出图

**未决关系的处理：** 默认图只展示已满足准入条件的关系。自动补查后仍无法确认的记录在内部保留，不伪装成已确认关系，也不要求用户逐项审核才能出图。

### 5.7 汇总与出图

**输入：** 当前已完成分析的数据集合；选了章节聚焦时只取对应章节范围（§5.7.1）。

**步骤：**

1. 人名以人名册对齐
2. 按（人物A, 人物B, 类型）合并
3. 计算展示分、应用软硬显示规则
4. 过滤过弱边 / 路人（规则可调，见 §5.7.6）
5. 生成图数据 → 前端展示

**视图（长篇更重要）：**

- 默认核心人物子图
- 以某人为中心的关系网络
- 按关系类型筛选（只看血缘 / 只看硬关系）
- 按势力分区浏览（见 §3.1、§5.7.4）
- 展开「更多」查看被压制的软关系

#### 5.7.1 章节聚焦

用于边读边查：读到某一章时，只看这一章有谁、他们之间是什么关系。默认仍是全书视图。

| 视图 | 人物 | 关系 |
|------|------|------|
| 全书（默认） | 全书人物，按 §5.7.6 过滤路人 | 全书已准入关系 |
| 第 N 章 | 只留第 N 章出场的人物；不按出场章数过滤路人（本章路人照常显示） | 这些人物之间、依据出现在第 N 章及以前的关系；依据在第 N 章的标为「本章」突出显示，更早确立的作为背景淡化显示 |
| 前 N 章（累计） | 第 1～N 章出场过的人物；出场章数只数前 N 章，再按 §5.7.6 过滤路人 | 依据出现在前 N 章内的关系 |

- 「出场」指人物出现在该章的人物列表里，含只被提及而未登场的人物
- 关系只显示前 N 章依据确立过的类型；详情里的章节与引文也只列前 N 章内的
- 单章 / 前 N 章视图的人物详情照常显示全书简介；单章视图另列此人在本章的关系依据与事件
- 类型 / 硬度筛选、人物聚焦、势力分区、导出在聚焦视图内照常可用；导出遵循所选范围并标注「第 N 章」或「前 N 章」
- 交互：章节选择器（输入或下拉，旁显示章节标题），可在全书 / 第 N 章 / 前 N 章之间切换，上一章 / 下一章快速翻动；被切掉的人物与关系不渲染（不灰显）
- 本功能**不是**防剧透保证：人物称呼、团体归属、重要度仍按全书结果；关系类型随剧情变化（如订婚→夫妻）不按进度重判

#### 5.7.2 渲染样式

以文字为主的节点图：

| 要素 | 说明 |
|------|------|
| 节点 | 圆点内显示人物首字，名字在下方；底色与描边取势力色，大小按重要度 |
| 边 | 线上标注关系类型；放得下才显示，人多的图放大或悬停 / 选中相关人物时再显示 |
| 线条样式 | 硬关系实线、中关系虚线、软关系点线 |
| 方向 | 无向关系不画箭头；有向关系画单向箭头，详情中显示双方角色，如「A（师父）→ B（徒弟）」 |
| 多关系方向 | 同一连线兼有有向与无向标签时，箭头表示有向标签；相反方向的关系分开显示，各自可选中查看依据 |
| 布局 | 势力分区 / 亲疏扇区可切换（见 §5.7.4）；人物可拖拽 |
| 悬停 | 高亮该人物与一度邻居及连边，其余淡出 |
| 点击 | 侧栏显示人物或关系详情（类型 + 章节 + 说明，有引文时展示原文） |
| 缩放 | 缩小时先隐藏龙套名字、再隐藏配角名字；主角名字与区块名保持可读 |

图谱可读性规则：

- 连线优先使用直线，只在会穿过沿途人物或与另一条关系重叠时采用平滑曲线绕行；重叠的关系保持各自可辨认、可选中，避免不必要的大幅绕行。
- 连线与姓名冲突时优先由姓名让位：姓名换到人物周围没有连线的一侧，连线只在小幅弯曲即可让开时才绕行。
- 姓名和关系文字共同避让；缩放、悬停、选中后仍不得强制叠放文字。放不下的关系文字可在浮窗和详情中查看。
- 姓名可根据周围空间显示在人物的不同方位；重要人物和当前关注人物优先保持姓名可读。
- 势力内的人物位置兼顾相互关系，减少不必要的交叉，同时保留势力归属与核心人物的位置语义。
- 拖动人物后，连线与文字按新位置重新避让；复杂网络允许交叉，但不应把多条关系叠成无法区分的一条。

#### 5.7.3 人物聚焦

**选中：** 单击人物或连线 → 描边高亮，侧栏显示详情；搜索人名 → 自动选中并把镜头推到此人。

**中心视图：** 双击人物，或在人物详情里选择以此人为中心 → 图收缩为以该人物为中心的一度关系网络，可回到全局视图。

| 要素 | 说明 |
|------|------|
| 中心人物 | 居中、高亮 |
| 一度关系 | 直接关系的人物与连线保留 |
| 无关人物与连线 | 不显示；回到全局视图后恢复 |

**侧栏人物卡：** 标签（性别、重要度等）、所属势力、全书简介（单章视图另列本章事件）、出场章节条、按硬 / 中 / 软分组的关系与依据。

**联动：** 与章节聚焦叠加生效——先切范围，再聚焦某人。

#### 5.7.4 布局模式与势力分区

> 势力定义见 §3.1。硬原则见 §4.4。

##### A. 两层正交信息

| 层 | 表达什么 | 视觉表现 |
|----|----------|----------|
| **势力（归属）** | 人属于哪个团体 | 平面分区 / 色块 / 外框 |
| **关系（连边）** | 两人之间是什么 | 线型、标签、线粗 |

禁止把「朋友」当成势力名；朋友是边，学校 / 教会才是块。

##### B. 布局模式

| 模式 | 定位 | 说明 |
|------|------|------|
| **势力分区** | 大图默认 / 主策略 | 团体块聚拢，块间弱连或经桥接人；百人级全景首选 |
| 亲疏扇区（主角中心） | 辅模式 | 适合已裁子集或聚焦后；不宜单独扛 100+ 全景 |

用户可切换布局，但产品默认与「大图可用」验收以势力分区为准。

##### C. 势力从哪里来

| 来源 | 说明 |
|------|------|
| 机构 / 场景实体 | 文中明确的学校、教会、门派、府邸名 |
| 共现 / 生活世界 | 同一阶段大量共现、跨阶段很少重叠 → 聚成「第 k 阶段」再命名 |
| 家族作团体 | 贾府等作为一个势力块；房支 / 辈分是块内结构 |

一人多势力：允许。人物本体落在主势力块；在其他势力里以「分身」再出现一次，规则如下：

- 只有主角、配角生成分身，龙套不生成；分身数量不设上限。
- 只在「有关系的势力」里生成：该人物属于这个势力，且与落在这个势力块里的人有关系。只是挂名、没有连线的势力不生成。
- 与某势力成员的关系画在该势力里的分身上，不再从主势力块拉长线过去；其余关系仍画在本体上。
- 分身用虚线头像框、略小于本体，颜色随所在势力。平时本体与分身之间不连线；悬停或选中其中任一个时，本体和所有分身一起高亮，并用淡色细线相连，表明是同一人。
- 点击、双击分身等同于操作该人物本身，详情只有一份。
- 人物详情列出此人在当前范围内所属的全部势力，主势力排最前并标明；未归属的人物不显示这一栏。
- 中心视图的中心人物只出现一次，不生成分身；亲疏扇区布局没有势力块，也不生成分身。

##### D. 与过滤、聚焦的关系

- 势力分区解决「百人怎么摆」；过滤解决「块内是否过密、路人是否该上图」——两者叠加，不是二选一
- 目标若是 100+ 可浏览大图：应分区优先，过滤阈值可放宽；若只做 20 人子集，则未验证大图能力
- 聚焦 / 搜索用于块内下钻与找人；全局秩序仍靠势力块
- 块内过密时：二级折叠或块内再筛，不退回取消分区

#### 5.7.5 导出

导出 **JSON**：人名册、势力、图数据（节点 + 边 + 证据）与各章结果；章节聚焦时按所选范围导出。

导出 **PNG**：用于宣传配图，以及用户保存到手机自己看或发出去，都要在手机上看得清。

| 规则 | 说明 |
|------|------|
| 内容 | 当前视图下的完整图，不只是屏幕上露出的部分；布局、势力分区、筛选、人物聚焦、章节聚焦如实反映 |
| 附带信息 | 书名、分析范围（全书 / 第 N 章 / 前 N 章）、图例（硬 / 中 / 软线型与势力颜色）、ZhiYing 水印 |
| 清晰度 | 在手机上双指放大后人名仍可辨认；人多的图不能因为整体缩小而糊成一片 |
| 文字 | 导出图里显示人名与主要关系文字，不依赖悬停才能看到 |
| 适用 | 示例书和自己的书都可导出；导出不占额度 |

#### 5.7.6 人物过滤（默认去路人）

长篇人物众多，不过滤会变成糊墙海报。默认过滤只出现极少数章节的路人，让图聚焦于有实际戏份的人物。

**出现次数的定义：**

采用**按章计数**：人物在某章的涉及人物列表中出现，计 1 次；同一章内提及多次仍计 1。

选择按章计数的理由：
- 与章级分析的产出天然对齐，无额外成本
- 计数来自本次汇总的数据；前 N 章视图按前 N 章重算（§5.7.1）
- 稳定可复现

**过滤交互：**

| 交互 | 说明 |
|------|------|
| 滑块 | 「最少出现 N 章」可调，默认值 = 2 |
| 显示被过滤数 | 如「已隐藏 87 位路人」 |
| 例外保留 | 即使低于阈值，若人物有硬关系（如夫妻 / 亲子），仍保留 |
| 与章节聚焦联动 | 前 N 章视图按前 N 章重算出现次数；单章视图不按出场章数过滤 |
| 与聚焦联动 | 被聚焦人物无视阈值强制显示 |

阈值不写死：不同书人物密度差异大，固定值对短书太松、对长书可能太紧，因此提供滑块让用户自行微调。

### 5.8 自动完成与人工纠错边界

系统自动完成身份归并、关系归一、未决补查与异常处理，直接产出可用关系图。核心用户尚未读过书，没有能力承担事实校对；不能把人工纠错设计成正常流程、失败处理的必经步骤或质量兜底。

**不做：** 人工合并人物、改正式名 / 别名、增删改关系标签、修改势力与成员归属。

**提供：** 查看人名册、证据与分析进度，触发单章重跑，调整过滤阈值、聚焦、布局与导出。这些是查看与操作能力，不要求用户判定书中事实；重跑结果仍由系统自动处理。

### 5.9 失败、发布与用量

- **不发布有缺章的结果：** 整书分析中只要有章节最终读取失败，本次不发布新结果，用户看到的仍是上一版（首次分析则暂无图），并告知哪些章节失败、原因是什么。
- **失败可续跑：** 成功章节的结果保留；用户再次启动分析时只补读失败章节，不重复消耗已成功的章节。用户也可选择全部重读。
- **取消与重跑失败同样不发布：** 用户取消分析，或单章重跑失败时，上一版结果保持可读不变。
- **用量可见：** token 数字只对管理员显示，包括本人条目的累计输入 / 输出 / 总 token 与本次任务消耗，以及后台全站、按用户、按书的汇总。普通用户与访客在书详情、分析进度及接口中均看不到 token；普通用户仍可查看自己的书数与分析字数额度（§5.13）。

### 5.10 删除书与清空分析

书架上每本书提供两个管理操作，都需用户二次确认，执行后不可恢复：

| 操作 | 结果 | 之后 |
|------|------|------|
| 删除书 | 书从本人书架消失；其他人的书与结果不受影响，已用分析额度不退还（§5.13） | 要再分析须重新上传 |
| 清空分析 | 清除本人可见的关系图、各章结果与任务记录，书回到「未分析」；本人累计 token 与已用分析额度保留，其他人的结果不受影响 | 再次分析从头读每一章，不沿用旧的章结果 |

- 书正在分析（含单章重跑）时两个操作都不可用，提示先停止分析。
- 正在查看的书被删除后，页面回到书架。

### 5.11 账号

| 规则 | 说明 |
|------|------|
| 注册 | 只能凭邀请码注册；管理员分批发放邀请码，每个邀请码有可用次数上限，用完失效 |
| 登录 | 用户名 + 密码；用户名不区分大小写，登录状态在同一浏览器保持，可主动退出 |
| 忘记密码 | 由管理员重置，不做自助找回；重置后该用户在所有浏览器的登录状态失效，需用新密码重新登录 |
| 管理员 | 生成邀请码、重置密码、维护示例书；后台的用量、模型、评测、账号与反馈管理只对管理员开放（§5.15–5.16） |
| 已有数据 | 启用账号时，已有未归属的测试书归入管理员账号，保留书籍与分析数据 |

### 5.12 按用户隔离

- 访客只能浏览已发布的示例书；上传和分析自己的书需要登录。
- 登录用户只能看到和操作自己上传的私有书，以及所有人可见的已发布示例书；书的章节、分析任务、结果与累计用量随书隔离，其他用户不能通过任何入口读取。
- 删除书、清空分析只影响本人的私有书（§5.10）。管理员同样不能读取或操作其他用户的私有书。
- 已发布示例书对访客和普通用户只读；管理员可重新分析配置为示例的书，发布新结果前仍展示上一版；示例书不能删除或清空分析。
- 管理员评测只使用自己的书，不使用其他用户的私有书。
- 不同用户上传同一个文件可直接获得已有完整分析结果（§5.14）；重新分析、单章重跑、清空和删除都只影响自己，看不到还有谁上传过。
- 用量额度按任务发起者归属（§5.13）；私有书反馈由书主提交，管理员查看反馈不获得该书的读取权限（§5.16）。

### 5.13 用量上限

上限由运营方在配置中调整，界面不提供管理入口。数值上限为 0 时不限。

| 上限 | 作用 |
|------|------|
| 每人书数 | 书架上最多几本，不含示例书；删除书释放书数名额 |
| 每人累计分析字数 | 整书分析与单章重跑按实际读取的字数累计；读到一半失败或被取消的章也计入，未开始与沿用已有抽取的章不计；删除书或清空分析不退还 |
| 单个文件大小 | 一本书的上传文件上限 |
| 每人同时分析 | 同一时间最多几个分析任务，含单章重跑 |
| 全站每日 token | 当天总消耗达到预算后不再接受新分析，进行中的任务继续完成 |

用户可见行为：

- 书架顶部显示本人已用 / 总额度（书数、字数）；不限的项目不显示。
- 上传或启动分析前，若会超出额度，直接拒绝并说明是哪一项超限、还剩多少；不先开始再中途停止。
- 全站预算用尽时提示「今日分析名额已满，请明天再试」；已有结果照常浏览。
- 一本书待分析字数超过剩余额度时整本拒绝，不做部分分析。
- 管理员不受每人书数、字数、同时分析上限约束，但文件大小上限照常，其分析照常计入全站每日 token。
- 秒传命中不计分析字数，不受剩余字数或当天分析名额限制，仍受上传大小和新增书数限制（§5.14）。

### 5.14 秒传

用户上传的文件如果别人（或示例书）已经完整分析过，直接拿到分析结果，不用等，也不花分析额度。

| 规则 | 说明 |
|------|------|
| 命中 | 上传的文件与某次分析所用的文件完全相同，且那次分析读完了全书、整书成功，用的是当前版本的分析方法 |
| 不命中 | 只读到第 N 章的结果、失败或取消而未发布的分析、正在进行中的分析、分析方法更新前的结果，都不用于秒传；此时照常分析、照常计入额度 |
| 上传 | 文件照常完整上传，由服务器比对；不提供「只发校验值、不传文件」的秒传，避免没有这本书的人凭校验值拿到原文摘录 |
| 效果 | 上传完成即可看图；提示「这本书已有分析结果，已直接加载」，不显示假的分析进度 |
| 额度 | 不计 token 与分析字数，计入书数 |
| 之后的操作 | 秒传得到的书与自己分析的书用法相同，可以重新分析、单章重跑、清空分析、删除，按实际读取的字数计入额度；这些操作只影响自己，其他人看到的结果不变 |
| 重新分析期间 | 与自己的书相同：重新分析完成前看到的仍是原来的结果 |
| 隐私 | 秒传不透露这本书还有谁上传过，也不透露其他用户的任何信息；本人条目累计用量为 0，token 仅管理员可见（§5.9） |
| 重复上传 | 自己书架上已有同一个文件时，不新增一本，直接打开已有的那本 |
| 示例书 | 与示例书相同的文件同样命中 |

### 5.15 后台管理

管理员专用的一个后台页面，把管理功能收到一起。访客与普通用户看不到入口，直接访问也被拒绝。

| 页签 | 内容 |
|------|------|
| 用量 | 全站今日与近 30 天每日 token；按用户列出累计分析字数、token、书数；按书列出 token，删除书仍保留已用记录 |
| 模型 | 各分析环节（读章、后处理、团体归纳）的模型与思考开关；修改对之后启动的分析生效，不用重启；可恢复部署配置与测试连接。页面提示更换模型或思考开关后，原配置结果不能再秒传 |
| 评测 | 现有评测功能，旧评测链接跳转到后台评测页签 |
| 账号 | 现有邀请码与重置密码管理 |
| 反馈 | 按书查看反馈快照、导出供评测整理；仅示例书可打开对应结果（§5.16） |

- token 可见范围见 §5.9；普通用户的书数与字数额度不变。
- 模型服务地址与 API Key 仍由部署配置提供，后台不能查看或修改。
- 用量上限仍只在部署配置里调整，后台只展示（§5.13）。

### 5.16 反馈

用户不改图，只报告问题（§5.8）。反馈不会改变分析结果，只供开发者改进和补充评测。

| 规则 | 说明 |
|------|------|
| 入口 | 人物详情、每种关系详情和势力块提供「这里不对」；图例里的势力也可反馈；顶部栏提供面向整个产品的通用反馈。需要登录，访客点击时提示登录 |
| 填写 | 类别和说明都可留空直接提交；类别包括人物重复、关系错误、势力不对、缺了人或关系、其他；说明最多 200 字 |
| 自动附带 | 对象反馈附带书、对象、当前分析范围、所见结果版本、提交时间以及提交时的书名和对象名称；通用反馈不附带书和对象 |
| 用户可见 | 成功后提示「已收到」；同一对象可以再次提交 |
| 管理员可见 | 在后台反馈页签按书查看、导出供人工整理评测样本；示例书反馈能跳转到当前人物或关系的一端，对象已不存在时明确提示；私有书仅展示反馈和名称快照，不能打开该书（§5.12） |
| 保留 | 重跑、清空分析或删除书后，已提交的反馈仍保留提交时的内容 |

### 5.17 示例书

书架预置几本已分析好的书，访客打开网站即可浏览，无需上传和等待。

| 规则 | 说明 |
|------|------|
| 选书 | 公版书，原著与所用版本（译本、校注本）都不能有版权风险；优先选人物多、势力分明的书，再配一本中篇 |
| 位置 | 书架上单独一组「示例」，与用户自己的书分开 |
| 链接 | 每本示例书有固定的公开链接，官网和宣传帖可以直接跳转，打开就是关系图；链接可带上人物或章节范围，打开即定位到对应视图 |
| 可做 | 浏览关系图、章节聚焦、人物聚焦、筛选、切换布局、查看人名册与证据、导出 |
| 不可做 | 访客和普通用户不能重跑、清空分析、删除；界面不显示这些操作，管理员维护权限见 §5.12 |
| 登录 | 不需要登录，访客可完整使用上面「可做」的全部操作；上传需要登录（§5.11–5.12） |
| 更新 | 示例书由管理员上传并分析；重新分析期间用户看到的仍是上一版 |
| 用量 | 浏览示例书不占用户额度 |

| 类 | 要求 |

## 8. 成功标准

成功不看「一次全对」，而看：

1. 中篇跑通：上传 → 章分析 → 归纳 → 出图
2. 打开图默认能读（路人过滤生效），不是密网
3. 点开一条关系能看到来源章节与说明；有引用时可查看原文依据
4. 聚焦某人能看清其关系网；导出 JSON 可用
5. 未读过书的用户无需人工合并、校图或审核关系，也能直接得到可用结果

**量化质量目标待定。** 评测口径见 DESIGN §7；分数门槛等积累几次基线后再定，确定后写回本节。

**评测页（维护工具）：** 管理员在前端评测页选择评测集，只使用自己拥有的书，可「重新分析并评测」（清空该书分析后整书重跑再评分），或只「评测当前结果」。页面展示总分与各项指标、逐章的漏检 / 误判及原因、未标注的结果，并能查看历史运行。没有运行记录时不编造分数。

## 9. 开放问题

| 问题 | 备注 |
|------|------|
| 量化质量目标 | 口径见 DESIGN §7，分数门槛待定 |
| 示例书选哪几本、用哪个版本 | 需确认版本无版权风险 |
| 各项用量上限的初始值 | 等单本书成本测准后确定（读章缓存、秒传命中率影响显著） |
| 不同来源的同一本书 | 秒传只认同一个文件；换了封面、元数据的文件不命中。之后按章节正文复用可省下大部分成本（见 todo） |
| 官网 | 页面内容与形式未定；只要求示例书能从官网跳转（§5.17） |
| 公网部署与合规 | 服务器地区、域名备案、生成式 AI 服务的合规要求；用户协议与隐私说明 |
| 手机端浏览 | 手机打开网页的体验尚未验证 |
