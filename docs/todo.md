## 测试约定

越接近真实使用的测试越重要，在精不在多。本项目以模型判断为主，纯函数单元测试价值低，不追求单测数量与覆盖率。

| 测试 | 验证内容 |
|---|---|
| Gherkin 验收（主力） | `acceptance/` 中的场景，从输入到用户可见结果；模型用可控替身，见 [acceptance/README](./acceptance/README.md) |
| 行为 / 集成测试 | 走真实 HTTP 与真实 SQLite：事务与回滚、重跑、发布一致性、取消、接口与进度契约 |
| 架构检查 | 领域不依赖框架；包无循环 |
| 真实模型评测 | 另行专项；保留抽取输入输出、判断结果、最终图与运行用量 |

- 只有规则复杂且容易写错的领域逻辑（身份合并、方向归一、软兜底时机）才值得单独测试
- 不给 DTO 字段写无意义断言；步骤未实现时保持未定义或失败，不写空步骤
