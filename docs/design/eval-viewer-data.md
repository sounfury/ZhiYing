# 评测原型接入现有文件

状态：实施中。用户已认可 `eval/viewer/index.html` 的界面，要求读取旧分析文件；不调整评分或 Gold 标注。

问题：原型的分数、诊断、章节与人物写死，跑分是计时器模拟；历史报告所引用的工作目录部分已不存在。本机还有无 Gold 的真实书籍分析，不能把其他书籍数据拼到历史报告上。

目标：保留深色卡片、四个页签、章节对照与人物网格，接入真实报告、Gold 与本地工作目录。无报告的书籍只展示分析结果，不生成质量分。搜索和分类叠加、选择运行产物、详情、JSON 下载、刷新均作用于实际选中数据。明确标示历史评分，取消虚假合格门禁与模拟执行。

方案：独立 Python 标准库本地只读服务，扫描 `eval/*/manifest.json`、对应 reports 和 `workspace/*/meta.json`，提供目录及选定数据接口。浏览器通过独立 JS 渲染。只允许目录枚举出的 ID 和固定静态资源，绑定回环地址，不接受任意文件路径。报告与当前 Gold 仅按端点和标签精确关联；无法匹配时展示不可关联，不能假定数组下标相同。报告的原始模型预测未保存时不伪造其完整列表。

范围：`eval/viewer`；产品事实写入 PRD 的离线诊断说明。不改主应用、模型流程、评分脚本或历史结果，不调用模型、不覆盖原始文件。

风险与验证：测试目录扫描、异常/缺失文件、无评分分析数据、不同运行切换、HTML 转义、筛选叠加、下载一致性。缺章不当空章成功，数据缺失显示不可用，浏览器验证布局和交互。服务每次刷新重读文件；仅本地小规模使用，不引入任务调度和数据写入。

实施顺序：读数据适配 → 动态 UI → 数据与浏览器验证 → 使用说明。回退仅需恢复原 HTML 并停止服务，数据文件不变。
